Bab 1.3

Hello, Cargo!

Cargo adalah build system sekaligus package manager resmi Rust. Hampir semua Rustacean memakai tool ini untuk mengelola proyek Rust mereka, karena Cargo menangani banyak pekerjaan sekaligus: mengompilasi kode, mengunduh pustaka (library) yang dibutuhkan kodemu, dan mengompilasi pustaka-pustaka itu. Pustaka yang dibutuhkan kodemu kita sebut dependency.

Program Rust paling sederhana, seperti yang kita tulis di subbab sebelumnya, tidak punya dependency apa pun. Kalau proyek "Hello, world!" tadi dibangun dengan Cargo, ia hanya akan memakai bagian Cargo yang menangani kompilasi kode. Seiring programmu makin kompleks, kamu akan menambah dependency, dan kalau proyekmu memakai Cargo sejak awal, menambah dependency jadi jauh lebih mudah.

Karena mayoritas besar proyek Rust memakai Cargo, sisa kursus ini mengasumsikan kamu juga memakainya. Cargo otomatis ikut terpasang kalau kamu menginstal Rust lewat installer resmi di subbab sebelumnya. Untuk memastikan, jalankan: 

$ cargo --version

Kalau muncul nomor versi, berarti Cargo sudah siap dipakai! Kalau muncul error seperti command not found, cek dokumentasi metode instalasi Rust yang kamu pakai untuk menginstal Cargo secara terpisah.

Membuat Proyek dengan Cargo

Mari kita buat proyek baru dengan Cargo dan lihat bedanya dengan proyek "Hello, world!" tadi. Kembali ke folder projects-mu, lalu jalankan (perintah ini sama persis di semua sistem operasi): 

$ cargo new hello_cargo
$ cd hello_cargo

Perintah pertama membuat folder dan proyek baru bernama hello_cargo. Cargo menaruh semua file proyek di dalam folder dengan nama yang sama.

Masuk ke folder hello_cargo dan lihat isinya. Cargo sudah membuatkan dua file dan satu folder untuk kita: file Cargo.toml dan folder src yang berisi file main.rs.

Cargo juga otomatis menginisialisasi repository Git baru beserta file .gitignore-nya. (File Git tidak akan dibuat kalau kamu menjalankan cargo new di dalam repository Git yang sudah ada. Kamu bisa mengubah perilaku ini dengan flag --vcs.)

ℹ️ Apa itu Git?

Git adalah sistem version control yang sangat umum dipakai. Kamu bisa mengganti cargo new untuk memakai version control lain, atau tanpa version control sama sekali, lewat flag --vcs. Jalankan cargo new --help untuk melihat semua opsi yang tersedia.

Buka Cargo.toml di text editor-mu. Isinya kurang lebih seperti ini:

Nama berkas: Cargo.toml

[package]
name = "hello_cargo"
version = "0.1.0"
edition = "2024"

[dependencies]

File ini memakai format TOML (Tom's Obvious, Minimal Language) — format konfigurasi yang dipakai Cargo.

  • Baris pertama, [package], adalah judul seksi yang menandakan baris-baris di bawahnya adalah konfigurasi sebuah package. Seiring kita menambah informasi ke file ini, seksi lain akan ditambahkan.
  • Tiga baris berikutnya menyimpan informasi yang dibutuhkan Cargo untuk mengompilasi programmu: nama, versi, dan edisi Rust yang dipakai (dibahas lebih lanjut di Lampiran E).
  • Baris terakhir, [dependencies], adalah awal dari seksi untuk mendaftarkan dependency proyekmu. Di Rust, paket kode disebut crate. Proyek ini belum butuh crate lain, tapi kita akan memakainya di proyek pertama Bab 2.

Sekarang buka src/main.rs:

Nama berkas: src/main.rs

fn main() {
    println!("Hello, world!");
}

Cargo sudah membuatkan program "Hello, world!" untukmu, persis seperti yang kita tulis manual sebelumnya! Sejauh ini, bedanya cuma: Cargo menaruh kode di dalam folder src, dan kita punya file konfigurasi Cargo.toml di folder paling atas.

Cargo mengharapkan semua source file-mu berada di dalam folder src. Folder proyek tingkat atas hanya untuk file README, lisensi, file konfigurasi, dan hal lain yang tidak berkaitan langsung dengan kode. Ada tempat untuk semuanya, dan semuanya ada pada tempatnya — begitulah Cargo membantumu tetap terorganisir.

💡 Sudah punya proyek tanpa Cargo?

Kalau kamu memulai proyek tanpa Cargo (seperti proyek "Hello, world!" tadi), kamu bisa mengonversinya: pindahkan kode ke folder src, lalu buat file Cargo.toml yang sesuai. Cara termudah membuat Cargo.toml itu adalah menjalankan cargo init.

Build dan Run Proyek Cargo

Sekarang mari lihat apa bedanya saat kita build dan jalankan program "Hello, world!" ini lewat Cargo. Dari folder hello_cargo, build proyekmu dengan: 

$ cargo build
   Compiling hello_cargo v0.1.0 (file:///projects/hello_cargo)
    Finished dev [unoptimized + debuginfo] target(s) in 2.85 secs

Perintah ini membuat file executable di target/debug/hello_cargo (atau target\debug\hello_cargo.exe di Windows), bukan di folder saat ini. Karena build default adalah debug build, Cargo menaruh binary-nya di folder bernama debug. Kamu bisa menjalankan executable-nya dengan: 

$ ./target/debug/hello_cargo # atau .\target\debug\hello_cargo.exe di Windows
Hello, world!

Kalau semua lancar, Hello, world! akan tercetak di terminal. Menjalankan cargo build untuk pertama kalinya juga membuat file baru di folder paling atas: Cargo.lock. File ini mencatat versi persis dari setiap dependency di proyekmu. Proyek ini belum punya dependency, jadi isinya masih tipis. Kamu tidak akan perlu mengubah file ini secara manual — Cargo yang mengelola isinya.

Kita baru saja build proyek dengan cargo build lalu menjalankannya lewat ./target/debug/hello_cargo — tapi kita juga bisa memakai cargo run untuk mengompilasi sekaligus menjalankan hasilnya dalam satu perintah: 

$ cargo run
    Finished dev [unoptimized + debuginfo] target(s) in 0.0 secs
     Running `target/debug/hello_cargo`
Hello, world!

Memakai cargo run lebih praktis daripada harus mengingat menjalankan cargo build lalu mengetik path lengkap ke binary-nya, jadi kebanyakan developer memakai cargo run.

Perhatikan bahwa kali ini kita tidak melihat output yang menandakan Cargo sedang meng-compile hello_cargo. Cargo tahu file sumbernya tidak berubah, jadi ia tidak build ulang — cukup jalankan binary yang sudah ada. Kalau kamu mengubah source code-nya, Cargo akan build ulang lebih dulu sebelum menjalankannya, dan kamu akan melihat output seperti ini: 

$ cargo run
   Compiling hello_cargo v0.1.0 (file:///projects/hello_cargo)
    Finished dev [unoptimized + debuginfo] target(s) in 0.33 secs
     Running `target/debug/hello_cargo`
Hello, world!

Cargo juga menyediakan perintah cargo check. Perintah ini dengan cepat memeriksa kodemu untuk memastikan bisa dikompilasi, tapi tidak menghasilkan file executable: 

$ cargo check
   Checking hello_cargo v0.1.0 (file:///projects/hello_cargo)
    Finished dev [unoptimized + debuginfo] target(s) in 0.32 secs

Kenapa kadang kamu tidak butuh file executable? Karena cargo check jauh lebih cepat daripada cargo build — ia melewati langkah menghasilkan file executable. Kalau kamu terus-menerus mengecek pekerjaanmu sambil menulis kode, memakai cargo check akan mempercepat proses untuk mengetahui apakah proyekmu masih bisa dikompilasi. Banyak Rustacean rutin menjalankan cargo check saat menulis program untuk memastikan kodenya tetap valid, lalu baru menjalankan cargo build ketika executable-nya benar-benar dibutuhkan.

💡 Rekap perintah Cargo yang sudah kita pelajari

  • cargo new — membuat proyek baru.
  • cargo build — meng-compile proyek.
  • cargo run — meng-compile sekaligus menjalankan proyek dalam satu langkah.
  • cargo check — meng-compile untuk mengecek error saja, tanpa menghasilkan binary.
  • Hasil build disimpan di folder target/debug, bukan di folder kode sumbernya.

Keuntungan tambahan memakai Cargo: perintah-perintah di atas sama persis di sistem operasi apa pun. Jadi mulai titik ini, kursus ini tidak akan lagi memberi instruksi terpisah untuk Linux/macOS vs Windows.

Build untuk Rilis (Release)

Ketika proyekmu akhirnya siap dirilis, pakai cargo build --release untuk mengompilasinya dengan optimisasi. Perintah ini akan membuat executable di target/release, bukan target/debug. Optimisasi ini membuat kode Rust-mu berjalan lebih cepat, tapi mengaktifkannya memperlama waktu kompilasi. Karena itulah ada dua profil build berbeda: satu untuk development (di mana kamu ingin build ulang dengan cepat dan sering), dan satu lagi untuk membangun program final yang akan diberikan ke pengguna — yang tidak akan di-build ulang berkali-kali dan harus berjalan secepat mungkin. Kalau kamu sedang mengukur performa (benchmarking) kodemu, pastikan menjalankan cargo build --release dan mengukur dari executable di target/release.

Cargo sebagai Konvensi Bersama

Untuk proyek sederhana, Cargo tidak memberi banyak nilai tambah dibanding memakai rustc langsung — tapi manfaatnya akan terasa begitu programmu makin rumit. Begitu program berkembang jadi banyak file atau butuh dependency, jauh lebih mudah membiarkan Cargo yang mengoordinasikan proses build.

Walaupun proyek hello_cargo ini sederhana, ia sudah memakai sebagian besar tooling nyata yang akan kamu pakai sepanjang karier Rust-mu. Faktanya, untuk bekerja pada proyek yang sudah ada, kamu bisa memakai perintah berikut untuk meng-clone kodenya lewat Git, masuk ke folder proyek itu, dan build: 

$ git clone example.org/someproject
$ cd someproject
$ cargo build

Untuk informasi lebih lanjut tentang Cargo, lihat dokumentasi resminya.

Ringkasan Bab 1

  • Menginstal versi stabil terbaru Rust lewat rustup.
  • Meng-update ke versi Rust yang lebih baru dengan rustup update.
  • Membuka dokumentasi lokal dengan rustup doc.
  • Menulis dan menjalankan program "Hello, world!" langsung dengan rustc.
  • Membuat dan menjalankan proyek baru memakai konvensi Cargo (cargo new, cargo build, cargo run, cargo check).

Ini saat yang pas untuk membangun program yang lebih besar supaya kamu terbiasa membaca dan menulis kode Rust. Di Bab 2, kita akan membangun program permainan tebak angka.
