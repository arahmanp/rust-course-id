Membuat Permainan Tebak Angka

Mari langsung terjun ke Rust dengan mengerjakan sebuah proyek bareng-bareng! Bab ini memperkenalkan beberapa konsep umum Rust dengan menunjukkan cara memakainya dalam program nyata. Kamu akan belajar tentang let, match, method, associated function, crate eksternal, dan banyak lagi! Di bab-bab selanjutnya, kita akan membahas ide-ide ini lebih mendalam — di bab ini, kamu cukup mempraktikkan dasar-dasarnya dulu.

Kita akan membuat masalah pemrograman klasik untuk pemula: permainan tebak angka. Begini cara kerjanya — program akan membuat sebuah angka acak antara 1 dan 100. Program lalu meminta pemain memasukkan tebakan. Setelah tebakan dimasukkan, program akan memberi tahu apakah tebakan itu terlalu rendah atau terlalu tinggi. Kalau tebakannya benar, permainan mencetak pesan selamat dan berhenti.

Menyiapkan Proyek Baru

Masuk ke folder projects yang kamu buat di Bab 1, lalu buat proyek baru dengan Cargo: 

$ cargo new guessing_game
$ cd guessing_game

Perintah pertama, cargo new, menerima nama proyek (guessing_game) sebagai argumen pertama. Perintah kedua berpindah ke folder proyek yang baru dibuat.

Lihat file Cargo.toml yang dihasilkan:

Nama berkas: Cargo.toml

[package]
name = "guessing_game"
version = "0.1.0"
edition = "2024"

[dependencies]

Seperti yang kamu lihat di Bab 1, cargo new menghasilkan program "Hello, world!" untukmu. Lihat file src/main.rs-nya:

Nama berkas: src/main.rs

fn main() {
    println!("Hello, world!");
}

Sekarang kompilasi dan jalankan program "Hello, world!" ini sekaligus dengan perintah cargo run: 

$ cargo run
   Compiling guessing_game v0.1.0 (file:///projects/guessing_game)
    Finished dev [unoptimized + debuginfo] target(s) in 1.50s
     Running `target/debug/guessing_game`
Hello, world!

Perintah run sangat berguna ketika kamu butuh iterasi cepat pada sebuah proyek, seperti yang akan sering kita lakukan di game ini — menguji tiap perubahan kecil sebelum lanjut ke langkah berikutnya.

Buka lagi file src/main.rs. Kita akan menulis semua kode di file ini.

Memproses Sebuah Tebakan

Bagian pertama program tebak angka akan meminta input pengguna, memproses input itu, dan memastikan bentuknya sesuai yang diharapkan. Untuk memulai, kita izinkan pemain memasukkan sebuah tebakan. Ketikkan kode berikut ke src/main.rs:

Nama berkas: src/main.rs

use std::io;

fn main() {
    println!("Tebak angkanya!");

    println!("Silakan masukkan tebakanmu.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Gagal membaca baris input");

    println!("Kamu menebak: {guess}");
}

Kode ini padat informasi, jadi mari kita bahas baris demi baris. Untuk mendapatkan input pengguna lalu mencetak hasilnya sebagai output, kita perlu membawa pustaka input/output io ke dalam scope. Pustaka io berasal dari standard library, yang dikenal sebagai std: 

use std::io;

ℹ️ Apa itu "prelude"?

Secara default, Rust punya sekumpulan item dari standard library yang otomatis dibawa ke scope setiap program — kumpulan ini disebut prelude. Kalau sebuah tipe yang ingin kamu pakai tidak ada di prelude, kamu harus membawanya ke scope secara eksplisit dengan pernyataan use, seperti std::io di atas — yang memberi kita berbagai fitur berguna, termasuk kemampuan menerima input pengguna.

Seperti yang kamu lihat di Bab 1, fungsi main adalah titik masuk program:

fn main() {

Sintaks fn mendeklarasikan fungsi baru; tanda kurung () menandakan tidak ada parameter; dan kurung kurawal { membuka badan fungsi.

Seperti juga sudah kamu pelajari, println! adalah macro yang mencetak string ke layar:

println!("Tebak angkanya!");

println!("Silakan masukkan tebakanmu.");

Kode ini mencetak sapaan tentang permainannya dan meminta input dari pengguna.

Menyimpan Nilai dengan Variabel

Selanjutnya, kita membuat sebuah variabel untuk menyimpan input pengguna:

let mut guess = String::new();

Sekarang program ini mulai menarik! Banyak hal terjadi di baris kecil ini. Kita memakai pernyataan let untuk membuat variabel. Contoh lain: 

let apples = 5;

Baris ini membuat variabel baru bernama apples dan mengikatnya (bind) ke nilai 5. Di Rust, variabel bersifat immutable (tidak bisa diubah) secara default — begitu sebuah variabel diberi nilai, nilai itu tidak akan berubah. Konsep ini akan kita bahas mendalam di subbab "Variabel dan Mutabilitas" Bab 3. Untuk membuat variabel mutable (bisa diubah), kita tambahkan mut sebelum nama variabelnya: 

let apples = 5; // immutable
let mut bananas = 5; // mutable

ℹ️ Komentar di Rust

Sintaks // memulai sebuah komentar yang berlanjut sampai akhir baris. Rust mengabaikan semua isi komentar. Kita akan bahas komentar lebih detail di subbab 3.4.

Kembali ke program tebak angka kita — sekarang kamu tahu bahwa let mut guess memperkenalkan sebuah variabel mutable bernama guess. Tanda sama dengan (=) memberi tahu Rust bahwa kita ingin mengikat sesuatu ke variabel ini sekarang. Di sebelah kanan tanda sama dengan adalah nilai yang diikat ke guess, yaitu hasil pemanggilan String::new, sebuah fungsi yang mengembalikan instance baru dari String. String adalah tipe string dari standard library yang bisa bertambah panjang (growable) dan berformat teks UTF-8.

Sintaks :: pada ::new menandakan bahwa new adalah associated function dari tipe String. Associated function adalah fungsi yang diimplementasikan pada sebuah tipe, dalam hal ini String. Fungsi new ini membuat string baru yang kosong. Kamu akan menemukan fungsi new di banyak tipe lain karena ini nama yang umum dipakai untuk fungsi yang membuat nilai baru dari suatu jenis.

Secara keseluruhan, baris let mut guess = String::new(); membuat sebuah variabel mutable yang saat ini terikat ke instance String baru yang kosong. Fiuh!

Menerima Input Pengguna

Ingat kita sudah membawa fungsionalitas input/output dari standard library lewat use std::io; di baris pertama program. Sekarang kita panggil fungsi stdin dari modul io, yang memungkinkan kita menangani input pengguna: 

io::stdin()
    .read_line(&mut guess)

Kalau kita tidak meng-import modul io lewat use std::io; di awal program, kita tetap bisa memakai fungsi ini dengan menulisnya sebagai std::io::stdin. Fungsi stdin mengembalikan instance dari std::io::Stdin, sebuah tipe yang merepresentasikan handle ke standard input terminal-mu.

Selanjutnya, baris .read_line(&mut guess) memanggil method read_line pada handle standard input untuk mendapatkan input dari pengguna. Kita juga mengoper &mut guess sebagai argumen ke read_line untuk memberi tahu string mana yang akan dipakai menyimpan input pengguna. Tugas lengkap read_line adalah mengambil apa pun yang diketik pengguna ke standard input dan menambahkannya (append) ke sebuah string (tanpa menimpa isinya), sehingga kita mengoper string itu sebagai argumen. Argumen string ini harus mutable supaya method-nya bisa mengubah isi string tersebut.

Tanda & menandakan bahwa argumen ini adalah sebuah referensi, yang memberi cara bagi beberapa bagian kodemu untuk mengakses satu data yang sama tanpa perlu menyalin data itu berkali-kali ke memori. Referensi adalah fitur yang cukup kompleks, dan salah satu keunggulan utama Rust adalah betapa aman dan mudahnya memakai referensi. Kamu belum perlu tahu detailnya untuk menyelesaikan program ini — untuk sekarang, cukup tahu bahwa seperti variabel, referensi juga immutable secara default. Karena itu kita menulis &mut guess, bukan &guess, supaya bisa diubah. (Bab 4 akan menjelaskan referensi lebih mendalam.)

Menangani Kemungkinan Gagal dengan Result

Kita masih membahas baris kode yang sama — bagian selanjutnya adalah method ini:

.expect("Gagal membaca baris input");

Kita bisa saja menulis kode ini sebagai satu baris panjang: io::stdin().read_line(&mut guess).expect("Gagal membaca baris input"); — tapi satu baris yang terlalu panjang sulit dibaca, jadi lebih baik dipecah. Menyisipkan baris baru untuk memecah pemanggilan method ber-rantai (.method_name()) adalah kebiasaan yang wajar.

Seperti disebutkan sebelumnya, read_line menaruh apa pun yang dimasukkan pengguna ke string yang kita oper, tapi ia juga mengembalikan nilai Result. Result adalah sebuah enumeration (sering disebut enum), yaitu tipe yang bisa berada dalam salah satu dari beberapa kemungkinan keadaan. Setiap kemungkinan keadaan itu kita sebut variant.

Bab 6 akan membahas enum lebih detail. Tujuan tipe Result ini adalah untuk mengkodekan informasi penanganan error.

Variant dari Result adalah Ok dan Err. Variant Ok menandakan operasinya berhasil, dan berisi nilai yang berhasil dihasilkan. Variant Err berarti operasinya gagal, dan berisi informasi tentang bagaimana atau kenapa operasi itu gagal.

Sama seperti nilai dari tipe apa pun, nilai bertipe Result juga punya method yang bisa dipanggil. Instance Result punya method expect. Kalau instance ini adalah nilai Err, expect akan membuat program crash dan menampilkan pesan yang kamu berikan sebagai argumennya. Kalau method read_line mengembalikan Err, kemungkinan besar itu berasal dari error sistem operasi yang mendasarinya. Kalau instance ini adalah nilai Ok, expect akan mengambil nilai yang dibungkus Ok dan mengembalikannya supaya bisa kamu pakai. Dalam kasus ini, nilai tersebut adalah jumlah byte dari input pengguna.

Kalau kamu tidak memanggil expect, program tetap akan berhasil dikompilasi, tapi kamu akan mendapat warning:

$ cargo build
   Compiling guessing_game v0.1.0 (file:///projects/guessing_game)
warning: unused `Result` that must be used
  --> src/main.rs:10:5
   |
10 |     io::stdin().read_line(&mut guess);
   |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
   |
   = note: this `Result` may be an `Err` variant, which should be handled
   = note: `#[warn(unused_must_use)]` (part of `#[warn(unused)]`) on by default
help: use `let _ = ...` to ignore the resulting value
   |
10 |     let _ = io::stdin().read_line(&mut guess);
   |     +++++++

warning: `guessing_game` (bin "guessing_game") generated 1 warning
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.59s

Rust memperingatkan bahwa kamu belum memakai nilai Result yang dikembalikan read_line, menandakan program belum menangani kemungkinan error.

Cara yang benar untuk menghilangkan warning ini adalah benar-benar menulis kode penanganan error, tapi dalam kasus kita, kita memang ingin program ini crash begitu ada masalah, jadi kita pakai expect. Kamu akan belajar cara memulihkan diri dari error di Bab 9.

Mencetak Nilai dengan Placeholder println!

Selain kurung kurawal penutup, hanya ada satu baris lagi yang perlu dibahas:

println!("Kamu menebak: {guess}");

Baris ini mencetak string yang sekarang berisi input pengguna. Tanda kurung kurawal {} adalah sebuah placeholder — bayangkan {} seperti capit kepiting kecil yang "menjepit" sebuah nilai di tempatnya. Saat mencetak nilai sebuah variabel, nama variabelnya bisa langsung diletakkan di dalam kurung kurawal. Saat mencetak hasil evaluasi sebuah ekspresi, letakkan kurung kurawal kosong di string format-nya, lalu ikuti string format itu dengan daftar ekspresi (dipisah koma) sesuai urutan placeholder-nya. Mencetak sebuah variabel sekaligus hasil ekspresi dalam satu pemanggilan println! akan terlihat seperti ini: 

let x = 5;
let y = 10;

println!("x = {x} and y + 2 = {}", y + 2);

Kode ini akan mencetak x = 5 and y + 2 = 12.

Membuat Angka Rahasia

Selanjutnya, kita perlu membuat angka rahasia yang akan ditebak pengguna. Angka rahasia ini harus berbeda setiap kali dimainkan supaya permainannya tetap seru dimainkan berkali-kali. Kita pakai angka acak antara 1 dan 100 supaya permainannya tidak terlalu sulit. Rust belum menyediakan fungsionalitas angka acak di standard library-nya. Tapi tim Rust menyediakan crate rand untuk kebutuhan itu.

Menambah Fungsionalitas dengan Crate

Ingat, crate adalah kumpulan file source code Rust. Proyek yang kita buat sejauh ini adalah binary crate, yaitu sesuatu yang bisa dieksekusi. Crate rand adalah library crate, yang berisi kode yang dirancang untuk dipakai di program lain dan tidak bisa dieksekusi sendiri.

Di sinilah kemampuan Cargo mengoordinasikan crate eksternal benar-benar bersinar. Sebelum bisa memakai rand, kita perlu mengubah file Cargo.toml untuk menyertakan crate rand sebagai dependency. Buka file itu dan tambahkan baris berikut di bawah header [dependencies] yang sudah dibuatkan Cargo. Pastikan menuliskan rand persis seperti ini, dengan nomor versi ini, atau contoh kode di kursus ini mungkin tidak akan bekerja:

Nama berkas: Cargo.toml

[dependencies]
rand = "0.10.1"

Di file Cargo.toml, semua yang mengikuti sebuah header adalah bagian dari seksi itu sampai seksi lain dimulai. Di [dependencies], kamu memberi tahu Cargo crate eksternal apa saja yang dibutuhkan proyekmu beserta versinya. Di sini, kita menentukan crate rand dengan spesifikasi versi semantik 0.10.1. Cargo memahami Semantic Versioning (sering disebut SemVer) — sebuah standar penulisan nomor versi. Spesifikasi 0.10.1 sebenarnya singkatan dari ^0.10.1, yang artinya versi berapa pun yang minimal 0.10.1 tapi di bawah 0.11.0.

Cargo menganggap versi-versi tersebut punya public API yang kompatibel dengan versi 0.10.1, dan spesifikasi ini memastikan kamu akan mendapat rilis patch terbaru yang masih bisa dikompilasi dengan kode di bab ini. Versi 0.11.0 ke atas tidak dijamin punya API yang sama seperti yang dipakai contoh-contoh berikut.

Sekarang, tanpa mengubah kode apa pun, mari build proyeknya:

$ cargo build
    Updating crates.io index
     Locking 8 packages to latest Rust 1.96.0 compatible versions
  Downloaded rand_core v0.10.1
  Downloaded chacha20 v0.10.1
  Downloaded rand v0.10.1
  Downloaded 3 crates (162.9KiB) in 0.59s
   Compiling libc v0.2.186
   Compiling rand_core v0.10.1
   Compiling getrandom v0.4.3
   Compiling cfg-if v1.0.4
   Compiling chacha20 v0.10.1
   Compiling rand v0.10.1
   Compiling guessing_game v0.1.0 (file:///projects/guessing_game)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 2.03s

Kamu mungkin melihat nomor versi berbeda (tapi semuanya tetap kompatibel berkat SemVer!) dan baris yang berbeda (tergantung sistem operasimu), dan urutan barisnya bisa berbeda-beda.

Ketika kita menyertakan dependency eksternal, Cargo mengambil versi terbaru dari semua yang dibutuhkan dependency itu dari registry — salinan data dari Crates.io. Crates.io adalah tempat komunitas Rust mempublikasikan proyek open source mereka untuk dipakai orang lain.

Setelah meng-update registry, Cargo memeriksa seksi [dependencies] dan mengunduh crate yang terdaftar yang belum ada. Dalam kasus ini, walaupun kita hanya mendaftarkan rand, Cargo juga mengambil crate lain yang dibutuhkan rand supaya bisa bekerja. Setelah semua crate terunduh, Rust mengompilasinya lalu mengompilasi proyek kita bersama semua dependency yang sudah tersedia.

Kalau kamu langsung menjalankan cargo build lagi tanpa perubahan apa pun, kamu tidak akan melihat output apa pun selain baris Finished. Cargo tahu ia sudah mengunduh dan mengompilasi dependency-nya, dan kamu belum mengubah apa pun di Cargo.toml. Cargo juga tahu kamu belum mengubah apa pun di kodemu, jadi ia juga tidak mengompilasi ulang kode itu.

Memastikan Build yang Reproducible

Cargo punya mekanisme yang memastikan kamu bisa membangun ulang hasil yang sama persis setiap kali kamu atau siapa pun membangun kodemu: Cargo hanya akan memakai versi dependency yang kamu tentukan sampai kamu bilang sebaliknya. Misalnya, minggu depan versi 0.10.2 dari crate rand rilis dengan perbaikan bug penting, tapi juga membawa regresi yang bisa merusak kodemu. Untuk mengatasi ini, Rust membuat file Cargo.lock saat pertama kali kamu menjalankan cargo build.

Saat proyek pertama kali di-build, Cargo menentukan semua versi dependency yang sesuai kriteria lalu menuliskannya ke Cargo.lock. Saat kamu build proyek ini di masa depan, Cargo akan melihat file Cargo.lock sudah ada dan memakai versi yang tercatat di sana, tanpa perlu menentukan ulang versi-versi itu dari nol. Ini membuat build-mu otomatis reproducible. Dengan kata lain, proyekmu akan tetap memakai versi 0.10.1 sampai kamu meng-upgrade-nya secara eksplisit. Karena Cargo.lock penting untuk reproducible build, file ini biasanya ikut disertakan di version control bersama kode proyekmu.

Meng-update Crate ke Versi Baru

Saat kamu benar-benar ingin meng-update sebuah crate, Cargo menyediakan perintah update, yang akan mengabaikan file Cargo.lock dan mencari semua versi terbaru yang sesuai spesifikasi di Cargo.toml. Cargo lalu menuliskan versi itu ke Cargo.lock. Kalau tidak, secara default Cargo hanya akan mencari versi di atas 0.10.1 dan di bawah 0.11.0. Kalau crate rand merilis dua versi baru 0.10.2 dan 0.999.0, menjalankan cargo update akan menampilkan: 

$ cargo update
    Updating crates.io index
     Locking 1 package to latest Rust 1.96.0 compatible version
    Updating rand v0.10.1 -> v0.10.2 (available: v0.999.0)

Cargo mengabaikan rilis 0.999.0. Kamu juga akan melihat perubahan di Cargo.lock yang mencatat versi rand yang sekarang dipakai adalah 0.10.2. Untuk memakai rand versi 0.999.0, kamu harus mengubah Cargo.toml secara eksplisit (jangan lakukan ini sungguhan — contoh-contoh berikutnya mengasumsikan kamu memakai rand versi 0.10): 

[dependencies]
rand = "0.999.0"

Cargo membuatnya sangat mudah untuk memakai ulang pustaka orang lain, sehingga Rustacean bisa menulis proyek yang lebih kecil, dirakit dari banyak package. Bab 14 akan membahas Cargo dan ekosistemnya lebih lanjut.

Membuat Angka Acak

Mari mulai memakai rand untuk membuat angka yang akan ditebak. Update src/main.rs:

Nama berkas: src/main.rs

use std::io;

use rand::prelude::*;

fn main() {
    println!("Tebak angkanya!");

    let secret_number = rand::rng().random_range(1..=100);

    println!("Angka rahasianya adalah: {secret_number}");

    println!("Silakan masukkan tebakanmu.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Gagal membaca baris input");

    println!("Kamu menebak: {guess}");
}

Pertama, kita tambahkan baris use rand::prelude::*;. Modul prelude berisi bagian-bagian yang paling umum dipakai dari crate rand, dan use membuat item-item itu tersedia di scope program kita.

Selanjutnya, kita menambahkan dua baris di tengah. Baris pertama memanggil fungsi rand::rng yang memberi kita generator angka acak tertentu — yang bekerja lokal di thread eksekusi saat ini dan di-seed oleh sistem operasi. Lalu, kita memanggil method random_range pada generator angka acak itu. Method ini didefinisikan oleh trait RngExt yang merupakan bagian dari modul rand::prelude yang kita bawa ke scope lewat use rand::prelude::*;. Method random_range menerima sebuah ekspresi range sebagai argumen dan menghasilkan angka acak dalam range itu. Bentuk ekspresi range yang kita pakai di sini adalah start..=end, yang inklusif di batas bawah maupun atas, jadi kita menulis 1..=100 untuk meminta angka antara 1 dan 100.

Fitur keren lain dari Cargo: menjalankan cargo doc --open akan membangun dokumentasi dari semua dependency-mu secara lokal dan membukanya di browser. Kalau kamu penasaran dengan fitur lain di rand, jalankan perintah ini lalu klik rand di sidebar kiri.

Baris baru kedua mencetak angka rahasianya. Ini berguna selama kita mengembangkan programnya supaya bisa diuji, tapi nanti akan kita hapus di versi final. Bukan permainan yang seru kalau programnya langsung mencetak jawabannya begitu dimulai!

Membandingkan Tebakan dengan Angka Rahasia

Sekarang kita punya input pengguna dan angka acak, kita bisa membandingkan keduanya. Perhatikan bahwa kode berikut belum bisa dikompilasi — akan kita jelaskan kenapa.

❌ Belum bisa dikompilasi
use std::cmp::Ordering;
use std::io;

use rand::prelude::*;

fn main() {
    // --snip--

    println!("Kamu menebak: {guess}");

    match guess.cmp(&secret_number) {
        Ordering::Less => println!("Terlalu kecil!"),
        Ordering::Greater => println!("Terlalu besar!"),
        Ordering::Equal => println!("Kamu menang!"),
    }
}

Pertama, kita tambahkan pernyataan use lain, membawa sebuah tipe bernama std::cmp::Ordering ke scope dari standard library. Tipe Ordering adalah enum lain, dengan variant Less, Greater, dan Equal. Ini adalah tiga kemungkinan hasil ketika kamu membandingkan dua nilai.

Lalu, kita tambahkan lima baris baru di bawah yang memakai tipe Ordering. Method cmp membandingkan dua nilai dan bisa dipanggil pada apa pun yang bisa dibandingkan. Method ini menerima referensi ke apa pun yang ingin kamu bandingkan — di sini, ia membandingkan guess dengan secret_number. Lalu method itu mengembalikan sebuah variant dari enum Ordering yang kita bawa ke scope lewat use. Kita pakai ekspresi match untuk menentukan apa yang harus dilakukan berdasarkan variant Ordering apa yang dikembalikan dari pemanggilan cmp.

Sebuah ekspresi match tersusun dari beberapa arm (lengan/cabang). Sebuah arm terdiri dari sebuah pattern untuk dicocokkan, dan kode yang dijalankan kalau nilai yang diberikan ke match cocok dengan pattern arm tersebut. Rust mengambil nilai yang diberikan ke match dan memeriksa pattern setiap arm secara berurutan. Pattern dan konstruksi match adalah fitur Rust yang sangat kuat — keduanya memungkinkan kamu mengekspresikan berbagai kemungkinan situasi yang mungkin ditemui kodemu, dan memastikan kamu menangani semuanya. Fitur-fitur ini akan dibahas mendalam di Bab 6 dan Bab 19.

Mari telusuri contoh dengan ekspresi match yang kita pakai di sini. Misalkan pengguna menebak 50 dan angka rahasia acaknya kali ini adalah 38.

Ketika kode membandingkan 50 dengan 38, method cmp akan mengembalikan Ordering::Greater karena 50 lebih besar dari 38. Ekspresi match mendapat nilai Ordering::Greater dan mulai memeriksa pattern tiap arm. Ia melihat pattern arm pertama, Ordering::Less, dan melihat bahwa nilai Ordering::Greater tidak cocok dengan Ordering::Less, sehingga ia mengabaikan kode di arm itu dan lanjut ke arm berikutnya. Pattern arm berikutnya adalah Ordering::Greater, yang cocok dengan Ordering::Greater! Kode terkait di arm itu akan dijalankan dan mencetak Terlalu besar! ke layar. Ekspresi match berhenti setelah arm pertama yang cocok ditemukan, jadi arm terakhir tidak akan diperiksa dalam skenario ini.

Inti dari error ini adalah mismatched types (tipe tidak cocok). Rust punya sistem tipe yang kuat dan statis. Tapi ia juga punya type inference (penyimpulan tipe otomatis). Ketika kita menulis let mut guess = String::new(), Rust bisa menyimpulkan bahwa guess seharusnya bertipe String tanpa kita perlu menuliskannya secara eksplisit. Sementara itu secret_number adalah tipe angka. Beberapa tipe angka di Rust bisa menampung nilai antara 1 dan 100: i32 (angka 32-bit), u32 (angka 32-bit tanpa tanda/unsigned), i64 (angka 64-bit), dan lain-lain. Kecuali ditentukan sebaliknya, Rust memakai i32 sebagai default — itulah tipe secret_number kecuali kamu menambahkan informasi tipe lain yang membuat Rust menyimpulkan tipe angka berbeda. Alasan error ini muncul: Rust tidak bisa membandingkan tipe string dengan tipe angka.

Pada akhirnya, kita ingin mengonversi String yang dibaca program sebagai input menjadi tipe angka, supaya bisa dibandingkan secara numerik dengan angka rahasia. Kita lakukan itu dengan menambahkan baris ini ke badan fungsi main: 

let guess: u32 = guess.trim().parse().expect("Tolong masukkan angka!");

Kita membuat sebuah variabel bernama guess. Tapi tunggu, bukankah program sudah punya variabel bernama guess? Betul, tapi Rust dengan baik hati mengizinkan kita men-shadow nilai guess sebelumnya dengan nilai baru. Shadowing memungkinkan kita memakai ulang nama variabel guess alih-alih dipaksa membuat dua variabel unik, misalnya guess_str dan guess. Kita akan bahas ini lebih detail di Bab 3, tapi untuk sekarang, ketahuilah bahwa fitur ini sering dipakai ketika kamu ingin mengonversi sebuah nilai dari satu tipe ke tipe lain.

Kita mengikat variabel baru ini ke ekspresi guess.trim().parse(). guess di ekspresi ini merujuk ke variabel guess yang asli yang berisi input dalam bentuk string. Method trim pada instance String akan menghapus whitespace di awal dan akhir, yang harus kita lakukan sebelum mengonversi string ke u32, yang hanya bisa berisi data numerik. Pengguna harus menekan Enter untuk memenuhi read_line dan memasukkan tebakannya, yang menambahkan karakter newline ke string. Misalnya kalau pengguna mengetik 5 lalu menekan Enter, guess akan terlihat seperti ini: 5\n. \n merepresentasikan "newline" (baris baru). (Di Windows, menekan Enter menghasilkan carriage return dan newline, \r\n.) Method trim menghapus \n atau \r\n itu, menyisakan hanya 5.

Method parse pada string mengonversi string menjadi tipe lain. Di sini, kita memakainya untuk mengonversi dari string menjadi angka. Kita perlu memberi tahu Rust tipe angka yang persis kita inginkan lewat let guess: u32. Tanda titik dua (:) setelah guess memberi tahu Rust bahwa kita akan mengumumkan (annotate) tipe variabelnya. Rust punya beberapa tipe angka bawaan; u32 yang kita pakai di sini adalah bilangan bulat 32-bit tanpa tanda (unsigned). Ini pilihan default yang bagus untuk angka positif kecil. Kamu akan belajar tipe angka lain di Bab 3.

Selain itu, anotasi u32 di contoh ini, ditambah perbandingan dengan secret_number, membuat Rust menyimpulkan bahwa secret_number juga seharusnya bertipe u32. Jadi, sekarang perbandingannya dilakukan antara dua nilai bertipe sama!

Method parse hanya bekerja pada karakter yang secara logis bisa dikonversi menjadi angka, sehingga bisa dengan mudah menyebabkan error. Misalnya, kalau string-nya berisi A👍%, tidak ada cara untuk mengonversinya menjadi angka. Karena bisa gagal, method parse mengembalikan tipe Result, sama seperti method read_line. Kita menangani Result ini dengan cara yang sama, memakai method expect lagi. Kalau parse mengembalikan variant Err karena tidak bisa membuat angka dari string-nya, pemanggilan expect akan membuat game crash dan mencetak pesan yang kita berikan. Kalau parse berhasil mengonversi string menjadi angka, ia akan mengembalikan variant Ok dari Result, dan expect akan mengembalikan angka yang kita inginkan dari nilai Ok tersebut.

Mengizinkan Banyak Tebakan dengan Loop

Keyword loop membuat sebuah loop tanpa henti (infinite loop). Kita tambahkan loop supaya pengguna punya lebih banyak kesempatan menebak:

Nama berkas: src/main.rs

// --snip--

    println!("Angka rahasianya adalah: {secret_number}");

    loop {
        println!("Silakan masukkan tebakanmu.");

        // --snip--

        match guess.cmp(&secret_number) {
            Ordering::Less => println!("Terlalu kecil!"),
            Ordering::Greater => println!("Terlalu besar!"),
            Ordering::Equal => println!("Kamu menang!"),
        }
    }
}

Seperti terlihat, kita memindahkan semuanya mulai dari prompt input tebakan ke dalam sebuah loop. Pastikan mengindentasi baris-baris di dalam loop empat spasi lagi, lalu jalankan lagi programnya. Program sekarang akan terus-menerus meminta tebakan lagi, yang justru memunculkan masalah baru: sepertinya pengguna tidak bisa berhenti!

Berhenti Setelah Menebak Benar

Mari program game-nya berhenti ketika pengguna menang, dengan menambahkan pernyataan break:

Nama berkas: src/main.rs

match guess.cmp(&secret_number) {
    Ordering::Less => println!("Terlalu kecil!"),
    Ordering::Greater => println!("Terlalu besar!"),
    Ordering::Equal => {
        println!("Kamu menang!");
        break;
    }
}

Menambahkan baris break setelah Kamu menang! membuat program keluar dari loop saat pengguna berhasil menebak angka rahasianya dengan benar. Keluar dari loop juga berarti keluar dari program, karena loop ini adalah bagian terakhir dari main.

Menangani Input Tidak Valid

Untuk lebih menyempurnakan perilaku game, alih-alih membuat program crash saat pengguna memasukkan sesuatu yang bukan angka, mari kita buat game mengabaikan input itu supaya pengguna bisa terus menebak. Kita bisa lakukan itu dengan mengubah baris tempat guess dikonversi dari String ke u32:

Nama berkas: src/main.rs

let guess: u32 = match guess.trim().parse() {
    Ok(num) => num,
    Err(_) => continue,
};

Kita beralih dari pemanggilan expect menjadi ekspresi match, untuk beralih dari "crash saat error" menjadi "menangani error". Ingat, parse mengembalikan tipe Result, dan Result adalah enum yang punya variant Ok dan Err. Kita memakai ekspresi match di sini, sama seperti yang kita lakukan dengan hasil Ordering dari method cmp.

Kalau parse berhasil mengubah string menjadi angka, ia akan mengembalikan nilai Ok yang berisi angka hasilnya. Nilai Ok itu akan cocok dengan pattern arm pertama, dan ekspresi match akan mengembalikan nilai num yang dihasilkan parse dan dibungkus di dalam Ok. Angka itu akan berakhir tepat di tempat yang kita mau, di variabel guess yang baru kita buat.

Kalau parse tidak berhasil mengubah string menjadi angka, ia akan mengembalikan nilai Err yang berisi informasi lebih lanjut tentang errornya. Nilai Err tidak cocok dengan pattern Ok(num) di arm pertama, tapi cocok dengan pattern Err(_) di arm kedua. Underscore _ adalah nilai catch-all (menampung semua) — di contoh ini, artinya kita ingin mencocokkan semua nilai Err, apa pun informasi di dalamnya. Jadi, program akan menjalankan kode arm kedua, continue, yang memberi tahu program untuk lanjut ke iterasi loop berikutnya dan meminta tebakan lain. Secara efektif, program ini mengabaikan semua error yang mungkin ditemui parse!

Sentuhan Akhir

Sip! Dengan satu penyesuaian kecil terakhir, kita akan menyelesaikan permainan tebak angka ini. Ingat, program masih mencetak angka rahasianya. Itu berguna untuk pengujian, tapi merusak keseruan game-nya. Mari hapus println! yang mencetak angka rahasia itu. Berikut kode final lengkapnya:

Nama berkas: src/main.rs

use std::cmp::Ordering;
use std::io;

use rand::prelude::*;

fn main() {
    println!("Tebak angkanya!");

    let secret_number = rand::rng().random_range(1..=100);

    loop {
        println!("Silakan masukkan tebakanmu.");

        let mut guess = String::new();

        io::stdin()
            .read_line(&mut guess)
            .expect("Gagal membaca baris input");

        let guess: u32 = match guess.trim().parse() {
            Ok(num) => num,
            Err(_) => continue,
        };

        println!("Kamu menebak: {guess}");

        match guess.cmp(&secret_number) {
            Ordering::Less => println!("Terlalu kecil!"),
            Ordering::Greater => println!("Terlalu besar!"),
            Ordering::Equal => {
                println!("Kamu menang!");
                break;
            }
        }
    }
}

Selamat, kamu berhasil membangun permainan tebak angka! 🎉

Ringkasan

  • Proyek ini adalah cara praktik langsung untuk mengenal banyak konsep baru Rust: let, match, fungsi, pemakaian crate eksternal, dan lainnya.
  • Result dan Ordering adalah enum — tipe yang bisa berupa salah satu dari beberapa variant, dan match memaksa kita menangani setiap kemungkinannya.
  • Variabel di Rust immutable secara default; tambahkan mut untuk membuatnya mutable.
  • Cargo mengelola dependency eksternal (crate) lewat Cargo.toml, dengan versi yang dikunci di Cargo.lock untuk build yang reproducible.
  • loop, break, dan continue mengontrol alur perulangan program.

Bab 3 akan membahas konsep-konsep yang dimiliki hampir semua bahasa pemrograman — variabel, tipe data, dan fungsi — dan menunjukkan cara memakainya di Rust secara lebih formal. Bab 4 akan membahas ownership, fitur yang membuat Rust berbeda dari bahasa lain. Bab 5 membahas struct dan method syntax, dan Bab 6 menjelaskan cara kerja enum.
