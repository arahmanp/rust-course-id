Bab 3.2

Tipe Data

Setiap nilai di Rust punya data type tertentu, yang memberi tahu Rust jenis data apa yang sedang ditentukan, supaya Rust tahu cara memproses data itu. Kita akan lihat dua kelompok tipe data: scalar dan compound (majemuk).

Ingat, Rust adalah bahasa statically typed, artinya Rust harus tahu tipe semua variabel saat compile-time. Compiler biasanya bisa menyimpulkan tipe yang kita mau berdasarkan nilai dan cara kita memakainya. Dalam kasus di mana banyak tipe memungkinkan — seperti saat kita mengonversi String menjadi tipe numerik memakai parse di Bab 2 — kita harus menambahkan anotasi tipe, seperti ini: 

let guess: u32 = "42".parse().expect("Bukan angka!");

Kalau kita tidak menambahkan anotasi tipe : u32 di atas, Rust akan menampilkan error berikut, yang berarti compiler butuh lebih banyak informasi dari kita untuk tahu tipe apa yang kita mau:

Kamu akan melihat anotasi tipe yang berbeda untuk tipe data lain.

Tipe Scalar

Tipe scalar merepresentasikan satu nilai tunggal. Rust punya empat tipe scalar utama: integer, floating-point, Boolean, dan karakter. Kamu mungkin mengenali tipe-tipe ini dari bahasa pemrograman lain. Mari lihat cara kerjanya di Rust.

Tipe Integer

Integer adalah angka tanpa komponen pecahan. Kita sudah memakai satu tipe integer di Bab 2, yaitu tipe u32. Deklarasi tipe ini menandakan bahwa nilai yang diasosiasikan dengannya seharusnya berupa integer unsigned (tipe integer signed diawali i, bukan u) yang memakai ruang 32 bit. Tabel berikut menunjukkan tipe integer bawaan Rust. Kamu bisa memakai varian apa pun ini untuk mendeklarasikan tipe nilai integer.

Setiap varian bisa berupa signed atau unsigned dan punya ukuran eksplisit. Signed dan unsigned merujuk pada apakah angka itu bisa bernilai negatif — dengan kata lain, apakah angkanya butuh tanda (signed) atau selalu positif sehingga tidak butuh tanda sama sekali (unsigned). Ini seperti menulis angka di kertas: kalau tandanya penting, angka ditulis dengan tanda plus atau minus; tapi kalau aman diasumsikan positif, angka ditulis tanpa tanda. Angka signed disimpan memakai representasi two's complement.

Setiap varian signed bisa menyimpan angka dari −(2n − 1) sampai 2n − 1 − 1 inklusif, di mana n adalah jumlah bit yang dipakai varian itu. Jadi, i8 bisa menyimpan angka dari −(27) sampai 27 − 1, yaitu −128 sampai 127. Varian unsigned bisa menyimpan angka dari 0 sampai 2n − 1, jadi u8 bisa menyimpan angka dari 0 sampai 28 − 1, yaitu 0 sampai 255.

Selain itu, tipe isize dan usize bergantung pada arsitektur komputer tempat programmu berjalan: 64 bit kalau di arsitektur 64-bit, dan 32 bit kalau di arsitektur 32-bit.

Kamu bisa menulis literal integer dalam berbagai bentuk berikut. Perhatikan bahwa literal angka yang bisa jadi beberapa tipe numerik mengizinkan akhiran tipe (type suffix), seperti 57u8, untuk menentukan tipenya. Literal angka juga bisa memakai _ sebagai pemisah visual supaya lebih mudah dibaca, seperti 1_000, yang nilainya sama seperti 1000.

Jadi bagaimana kamu tahu tipe integer mana yang harus dipakai? Kalau ragu, default Rust umumnya titik awal yang bagus: tipe integer default-nya adalah i32. Situasi utama di mana kamu akan memakai isize atau usize adalah saat mengindeks sejenis koleksi data.

⚠️ Integer Overflow

Misalkan kamu punya variabel bertipe u8 yang bisa menampung nilai antara 0 dan 255. Kalau kamu coba ubah variabel itu ke nilai di luar rentang itu, misalnya 256, akan terjadi integer overflow, yang bisa menghasilkan salah satu dari dua perilaku:

  • Saat compile dalam mode debug, Rust menyertakan pengecekan integer overflow yang membuat programmu panic (crash) saat runtime kalau ini terjadi.
  • Saat compile dalam mode release (memakai flag --release), Rust tidak menyertakan pengecekan itu. Sebaliknya, kalau overflow terjadi, Rust melakukan two's complement wrapping: nilai yang melebihi maksimum tipe itu akan "berputar balik" ke nilai minimum yang bisa ditampung tipe itu. Untuk u8, nilai 256 menjadi 0, nilai 257 menjadi 1, dan seterusnya. Program tidak akan panic, tapi variabelnya akan bernilai sesuatu yang mungkin bukan yang kamu harapkan. Mengandalkan perilaku wrapping ini dianggap sebagai kesalahan.

Untuk menangani kemungkinan overflow secara eksplisit, standard library menyediakan beberapa keluarga method pada tipe numerik primitif: wrapping_* (selalu wrap di semua mode), checked_* (mengembalikan None kalau overflow), overflowing_* (mengembalikan nilai plus Boolean penanda overflow), dan saturating_* (mentok di nilai minimum/maksimum tipe itu).

Tipe Floating-Point

Rust juga punya dua tipe primitif untuk floating-point number (angka desimal): f32 dan f64, berukuran 32 bit dan 64 bit. Tipe default-nya adalah f64, karena di CPU modern kecepatannya kurang lebih sama dengan f32 tapi dengan presisi lebih tinggi. Semua tipe floating-point bersifat signed.

Nama berkas: src/main.rs

fn main() {
    let x = 2.0; // f64

    let y: f32 = 3.0; // f32
}

Angka floating-point direpresentasikan sesuai standar IEEE-754.

Operasi Numerik

Rust mendukung operasi matematika dasar yang kamu harapkan untuk semua tipe angka: penjumlahan, pengurangan, perkalian, pembagian, dan sisa bagi (remainder/modulo). Pembagian integer dipangkas (truncate) ke arah nol menuju integer terdekat.

Nama berkas: src/main.rs

fn main() {
    // penjumlahan
    let sum = 5 + 10;

    // pengurangan
    let difference = 95.5 - 4.3;

    // perkalian
    let product = 4 * 30;

    // pembagian
    let quotient = 56.7 / 32.2;
    let truncated = -5 / 3; // hasilnya -1

    // sisa bagi (modulo)
    let remainder = 43 % 5;
}

Setiap ekspresi di pernyataan ini memakai operator matematika dan dievaluasi menjadi satu nilai, yang lalu diikat ke sebuah variabel. Lampiran B berisi daftar lengkap semua operator yang disediakan Rust.

Tipe Boolean

Seperti kebanyakan bahasa pemrograman lain, tipe Boolean di Rust punya dua kemungkinan nilai: true dan false. Boolean berukuran satu byte. Tipe Boolean di Rust ditulis dengan bool. Contoh:

Nama berkas: src/main.rs

fn main() {
    let t = true;

    let f: bool = false; // dengan anotasi tipe eksplisit
}

Cara utama memakai nilai Boolean adalah lewat kondisional, seperti ekspresi if. Kita akan bahas cara kerja if di subbab 3.5 (Alur Kontrol).

Tipe Karakter

Tipe char di Rust adalah tipe alfabet paling primitif di bahasa ini. Berikut contoh mendeklarasikan nilai char:

Nama berkas: src/main.rs

fn main() {
    let c = 'z';
    let z: char = 'ℤ'; // dengan anotasi tipe eksplisit
    let heart_eyed_cat = '😻';
}

Perhatikan kita menuliskan literal char dengan tanda kutip tunggal, berbeda dari literal string yang memakai tanda kutip ganda. Tipe char di Rust berukuran 4 byte dan merepresentasikan sebuah nilai skalar Unicode, artinya ia bisa merepresentasikan jauh lebih banyak daripada sekadar ASCII. Huruf beraksen; karakter Mandarin, Jepang, Korea; emoji; dan zero-width space semuanya nilai char yang valid di Rust. Nilai skalar Unicode berkisar dari U+0000 sampai U+D7FF dan U+E000 sampai U+10FFFF inklusif. Tapi, "karakter" sebenarnya bukan konsep yang benar-benar ada di Unicode, jadi intuisi manusiawi kamu tentang apa itu "karakter" mungkin tidak selalu cocok dengan apa itu char di Rust. Topik ini akan dibahas detail di Bab 8 (Storing UTF-8 Encoded Text with Strings).

Tipe Compound (Majemuk)

Tipe compound bisa mengelompokkan beberapa nilai menjadi satu tipe. Rust punya dua tipe compound primitif: tuple dan array.

Tipe Tuple

Tuple adalah cara umum untuk mengelompokkan sejumlah nilai dengan berbagai tipe menjadi satu tipe compound. Tuple punya panjang tetap: begitu dideklarasikan, ukurannya tidak bisa bertambah atau berkurang.

Kita membuat tuple dengan menulis daftar nilai yang dipisah koma di dalam tanda kurung. Setiap posisi di tuple punya tipe, dan tipe nilai yang berbeda-beda di dalam tuple tidak harus sama. Kita tambahkan anotasi tipe opsional di contoh ini:

Nama berkas: src/main.rs

fn main() {
    let tup: (i32, f64, u8) = (500, 6.4, 1);
}

Variabel tup terikat ke seluruh tuple, karena tuple dianggap sebagai satu elemen compound tunggal. Untuk mengambil nilai-nilai individualnya, kita bisa memakai pattern matching untuk men-destructure nilai tuple, seperti ini:

Nama berkas: src/main.rs

fn main() {
    let tup = (500, 6.4, 1);

    let (x, y, z) = tup;

    println!("Nilai y adalah: {y}");
}

Program ini pertama membuat sebuah tuple dan mengikatnya ke variabel tup. Lalu ia memakai sebuah pattern dengan let untuk mengambil tup dan mengubahnya menjadi tiga variabel terpisah, x, y, dan z. Ini disebut destructuring karena memecah satu tuple menjadi tiga bagian. Terakhir, program mencetak nilai y, yaitu 6.4.

Kita juga bisa mengakses elemen tuple langsung memakai titik (.) diikuti indeks nilai yang ingin diakses:

Nama berkas: src/main.rs

fn main() {
    let x: (i32, f64, u8) = (500, 6.4, 1);

    let five_hundred = x.0;

    let six_point_four = x.1;

    let one = x.2;
}

Program ini membuat tuple x lalu mengakses setiap elemennya memakai indeksnya masing-masing. Seperti kebanyakan bahasa pemrograman lain, indeks pertama di sebuah tuple adalah 0.

Tuple tanpa nilai apa pun punya nama khusus, unit. Nilai ini dan tipenya sama-sama ditulis () dan merepresentasikan nilai kosong atau tipe kembalian kosong. Ekspresi secara implisit mengembalikan nilai unit kalau ia tidak mengembalikan nilai lain.

Tipe Array

Cara lain untuk punya kumpulan beberapa nilai adalah dengan array. Berbeda dari tuple, setiap elemen array harus bertipe sama. Berbeda dari array di beberapa bahasa lain, array di Rust punya panjang tetap.

Kita menulis nilai array sebagai daftar dipisah koma di dalam kurung siku:

Nama berkas: src/main.rs

fn main() {
    let a = [1, 2, 3, 4, 5];
}

Array berguna ketika kamu ingin datamu dialokasikan di stack — sama seperti tipe lain yang sudah kita lihat sejauh ini — bukan di heap (kita akan bahas stack dan heap lebih lanjut di Bab 4), atau ketika kamu ingin memastikan selalu punya jumlah elemen tetap. Array tidak sefleksibel tipe vector. Vector adalah tipe koleksi serupa dari standard library yang boleh bertambah atau berkurang ukurannya karena isinya hidup di heap. Kalau kamu ragu harus pakai array atau vector, kemungkinan besar kamu sebaiknya pakai vector. Bab 8 membahas vector lebih detail.

Tapi, array lebih berguna ketika kamu tahu jumlah elemennya tidak akan perlu berubah. Misalnya, kalau kamu memakai nama-nama bulan dalam sebuah program, kamu mungkin akan memakai array daripada vector karena kamu tahu isinya akan selalu 12 elemen: 

let months = ["January", "February", "March", "April", "May", "June", "July",
              "August", "September", "October", "November", "December"];

Kamu menulis tipe sebuah array dengan kurung siku berisi tipe tiap elemennya, titik koma, lalu jumlah elemen dalam array itu: 

let a: [i32; 5] = [1, 2, 3, 4, 5];

Di sini, i32 adalah tipe setiap elemennya. Setelah titik koma, angka 5 menandakan array ini berisi lima elemen.

Kamu juga bisa menginisialisasi array supaya berisi nilai yang sama untuk setiap elemen, dengan menuliskan nilai awal diikuti titik koma, lalu panjang arraynya di dalam kurung siku: 

let a = [3; 5];

Array bernama a ini akan berisi 5 elemen yang semuanya diset ke nilai 3 pada awalnya. Ini sama saja dengan menulis let a = [3, 3, 3, 3, 3];, tapi dengan cara yang lebih ringkas.

Mengakses Elemen Array

Array adalah satu blok memori berukuran tetap dan sudah diketahui, yang bisa dialokasikan di stack. Kamu bisa mengakses elemen array memakai indexing, seperti ini:

Nama berkas: src/main.rs

fn main() {
    let a = [1, 2, 3, 4, 5];

    let first = a[0];
    let second = a[1];
}

Di contoh ini, variabel first akan mendapat nilai 1 karena itu nilai di indeks [0] dalam array. Variabel second akan mendapat nilai 2 dari indeks [1].

Mengakses Elemen Array yang Tidak Valid

Mari lihat apa yang terjadi kalau kamu mencoba mengakses elemen array melewati ujung arraynya. Katakanlah kamu jalankan kode berikut, mirip permainan tebak angka di Bab 2, untuk mendapatkan indeks array dari pengguna:

Nama berkas: src/main.rs

use std::io;

fn main() {
    let a = [1, 2, 3, 4, 5];

    println!("Silakan masukkan indeks array.");

    let mut index = String::new();

    io::stdin()
        .read_line(&mut index)
        .expect("Gagal membaca baris input");

    let index: usize = index
        .trim()
        .parse()
        .expect("Indeks yang dimasukkan bukan angka");

    let element = a[index];

    println!("Nilai elemen di indeks {index} adalah: {element}");
}

Kode ini berhasil dikompilasi. Kalau kamu jalankan dengan cargo run dan masukkan 0, 1, 2, 3, atau 4, program akan mencetak nilai yang sesuai di indeks itu. Tapi kalau kamu masukkan angka melebihi ujung array, misalnya 10, kamu akan melihat output seperti ini: 

thread 'main' panicked at src/main.rs:19:19:
index out of bounds: the len is 5 but the index is 10
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace

Program menghasilkan error runtime di titik ketika ia memakai nilai yang tidak valid dalam operasi indexing. Program keluar dengan pesan error dan tidak menjalankan println! terakhir. Ketika kamu mencoba mengakses sebuah elemen memakai indexing, Rust akan memeriksa bahwa indeks yang kamu tentukan lebih kecil dari panjang arraynya. Kalau indeksnya sama dengan atau lebih besar dari panjang itu, Rust akan panic. Pengecekan ini harus terjadi saat runtime, khususnya di kasus ini, karena compiler tidak mungkin tahu nilai apa yang akan dimasukkan pengguna saat program dijalankan nanti.

ℹ️ Ini contoh keamanan memori Rust dalam aksi

Di banyak bahasa low-level, pengecekan semacam ini tidak dilakukan, dan ketika kamu memberikan indeks yang salah, memori yang tidak valid bisa diakses. Rust melindungimu dari jenis error ini dengan langsung keluar (panic), bukannya mengizinkan akses memori itu dan terus berjalan. Bab 9 membahas lebih lanjut soal penanganan error di Rust dan cara menulis kode yang aman tanpa panic maupun akses memori yang tidak valid.

Kenapa Rust memakai i32 sebagai tipe integer default, bukan misalnya i8 yang lebih hemat memori?

Ringkasan

  • Tipe scalar: integer (i8...i128, u8...u128, isize/usize), float (f32/f64), bool, dan char (4 byte, Unicode scalar value).
  • Integer overflow menyebabkan panic di mode debug, dan "wrap around" di mode release — keduanya bukan perilaku yang boleh diandalkan.
  • Tuple mengelompokkan nilai dengan tipe berbeda-beda, panjang tetap, diakses lewat destructuring atau .0, .1, dst.
  • Array mengelompokkan nilai bertipe sama, panjang tetap, dialokasikan di stack, dan diakses lewat indexing a[i] — akses di luar batas menyebabkan panic saat runtime.
