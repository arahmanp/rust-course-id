Bab 3.3

Fungsi

Fungsi ada di mana-mana dalam kode Rust. Kamu sudah melihat salah satu fungsi terpenting di bahasa ini: fungsi main, yang menjadi titik masuk banyak program. Kamu juga sudah melihat keyword fn, yang dipakai untuk mendeklarasikan fungsi baru.

Kode Rust memakai snake case sebagai gaya konvensional untuk nama fungsi dan variabel — semua huruf kecil, dengan underscore memisahkan kata. Berikut program berisi contoh definisi fungsi:

Nama berkas: src/main.rs

fn main() {
    println!("Hello, world!");

    another_function();
}

fn another_function() {
    println!("Fungsi lain.");
}

Kita mendefinisikan fungsi di Rust dengan mengetik fn diikuti nama fungsi dan sepasang tanda kurung. Kurung kurawal memberi tahu compiler di mana badan fungsi dimulai dan berakhir.

Kita bisa memanggil fungsi apa pun yang sudah kita definisikan dengan mengetik namanya diikuti sepasang tanda kurung. Karena another_function didefinisikan dalam program ini, ia bisa dipanggil dari dalam fungsi main. Perhatikan kita mendefinisikan another_function setelah fungsi main di source code-nya — kita juga bisa mendefinisikannya sebelum main. Rust tidak peduli di mana kamu mendefinisikan fungsimu, yang penting fungsi itu didefinisikan di suatu scope yang bisa "dilihat" oleh pemanggilnya.

Mari mulai proyek binary baru bernama functions untuk mengeksplorasi fungsi lebih jauh. Taruh contoh another_function di src/main.rs dan jalankan. Kamu akan melihat output: 

$ cargo run
   Compiling functions v0.1.0 (file:///projects/functions)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.28s
     Running `target/debug/functions`
Hello, world!
Fungsi lain.

Baris-baris dijalankan sesuai urutan kemunculannya dalam fungsi main. Pertama pesan "Hello, world!" dicetak, lalu another_function dipanggil dan pesannya dicetak.

Parameter

Kita bisa mendefinisikan fungsi supaya punya parameter — variabel khusus yang menjadi bagian dari signature sebuah fungsi. Ketika sebuah fungsi punya parameter, kamu bisa memberinya nilai konkret untuk parameter tersebut. Secara teknis, nilai konkret itu disebut argumen, tapi dalam percakapan sehari-hari, orang cenderung memakai kata "parameter" dan "argumen" secara bergantian, baik untuk variabel di definisi fungsi maupun nilai konkret yang dioper saat memanggil fungsi.

Di versi another_function ini kita tambahkan parameter:

Nama berkas: src/main.rs

fn main() {
    another_function(5);
}

fn another_function(x: i32) {
    println!("Nilai x adalah: {x}");
}

Coba jalankan program ini; kamu akan mendapat output:

$ cargo run
   Compiling functions v0.1.0 (file:///projects/functions)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 1.21s
     Running `target/debug/functions`
Nilai x adalah: 5

Deklarasi another_function punya satu parameter bernama x. Tipe x ditentukan sebagai i32. Ketika kita mengoper 5 ke another_function, macro println! menaruh 5 di posisi kurung kurawal berisi x dalam string format-nya.

Di signature fungsi, kamu wajib mendeklarasikan tipe setiap parameter. Ini keputusan desain yang disengaja di Rust: mewajibkan anotasi tipe di definisi fungsi berarti compiler hampir tidak pernah butuh kamu menuliskannya lagi di bagian lain kode untuk mengetahui tipe apa yang kamu maksud. Compiler juga bisa memberi pesan error yang lebih membantu kalau ia tahu tipe apa yang diharapkan fungsi itu.

Saat mendefinisikan banyak parameter, pisahkan deklarasinya dengan koma:

Nama berkas: src/main.rs

fn main() {
    print_labeled_measurement(5, 'h');
}

fn print_labeled_measurement(value: i32, unit_label: char) {
    println!("Ukurannya adalah: {value}{unit_label}");
}

Contoh ini membuat fungsi bernama print_labeled_measurement dengan dua parameter. Parameter pertama bernama value bertipe i32. Parameter kedua bernama unit_label bertipe char. Fungsi ini lalu mencetak teks berisi value dan unit_label.

Mari jalankan kode ini dengan cargo run:

$ cargo run
   Compiling functions v0.1.0 (file:///projects/functions)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.31s
     Running `target/debug/functions`
Ukurannya adalah: 5h

Karena kita memanggil fungsi ini dengan 5 sebagai nilai untuk value dan 'h' untuk unit_label, output program berisi nilai-nilai itu.

Statement dan Ekspresi

Badan fungsi tersusun dari serangkaian statement yang secara opsional diakhiri dengan sebuah ekspresi. Sejauh ini, fungsi yang kita bahas belum menyertakan ekspresi penutup, tapi kamu sudah melihat ekspresi sebagai bagian dari sebuah statement. Karena Rust adalah bahasa berbasis ekspresi, ini perbedaan penting untuk dipahami. Bahasa lain tidak selalu punya perbedaan yang sama, jadi mari kita lihat apa itu statement dan ekspresi, dan bagaimana perbedaannya memengaruhi badan fungsi.

  • Statement adalah instruksi yang melakukan sebuah aksi dan tidak mengembalikan nilai.
  • Ekspresi dievaluasi menjadi sebuah nilai hasil.

Mari lihat beberapa contoh.

Sebenarnya kita sudah memakai statement dan ekspresi. Membuat variabel dan memberinya nilai dengan keyword let adalah statement. Di contoh berikut, let y = 6; adalah statement.

Nama berkas: src/main.rs

fn main() {
    let y = 6;
}

Definisi fungsi juga statement — seluruh contoh sebelumnya sendiri adalah sebuah statement. (Seperti akan kita lihat sebentar lagi, memanggil sebuah fungsi bukan statement.)

Statement tidak mengembalikan nilai. Karena itu, kamu tidak bisa menetapkan sebuah statement let ke variabel lain, seperti yang dicoba kode berikut — kamu akan mendapat error:

❌ Belum bisa dikompilasi

Nama berkas: src/main.rs

fn main() {
    let x = (let y = 6);
}

Ketika kamu jalankan program ini, error yang muncul terlihat seperti:

$ cargo run
   Compiling functions v0.1.0 (file:///projects/functions)
error: expected expression, found `let` statement
 --> src/main.rs:2:14
  |
2 |     let x = (let y = 6);
  |              ^^^
  |
  = note: only supported directly in conditions of `if` and `while` expressions

warning: unnecessary parentheses around assigned value
 --> src/main.rs:2:13
  |
2 |     let x = (let y = 6);
  |             ^         ^
  |
  = note: `#[warn(unused_parens)]` (part of `#[warn(unused)]`) on by default

warning: `functions` (bin "functions") generated 1 warning
error: could not compile `functions` (bin "functions") due to 1 previous error; 1 warning emitted

Statement let y = 6 tidak mengembalikan nilai, jadi tidak ada apa pun untuk diikat oleh x. Ini berbeda dari yang terjadi di bahasa lain seperti C dan Ruby, di mana assignment mengembalikan nilai dari assignment itu sendiri. Di bahasa-bahasa itu, kamu bisa menulis x = y = 6 sehingga x dan y sama-sama bernilai 6 — itu tidak berlaku di Rust.

Ekspresi dievaluasi menjadi sebuah nilai, dan sebagian besar sisa kode yang akan kamu tulis di Rust adalah ekspresi. Ambil contoh operasi matematika seperti 5 + 6, yang merupakan ekspresi yang dievaluasi menjadi nilai 11. Ekspresi bisa menjadi bagian dari statement: di contoh sebelumnya, angka 6 di statement let y = 6; adalah ekspresi yang dievaluasi menjadi nilai 6. Memanggil fungsi adalah ekspresi. Memanggil macro adalah ekspresi. Blok scope baru yang dibuat dengan kurung kurawal juga ekspresi, misalnya:

Nama berkas: src/main.rs

fn main() {
    let y = {
        let x = 3;
        x + 1
    };

    println!("Nilai y adalah: {y}");
}

Ekspresi ini:

{
    let x = 3;
    x + 1
}

adalah sebuah blok yang, dalam kasus ini, dievaluasi menjadi 4. Nilai itu terikat ke y sebagai bagian dari statement let. Perhatikan baris x + 1 tidak diakhiri titik koma, berbeda dari kebanyakan baris yang sudah kamu lihat sejauh ini. Ekspresi tidak menyertakan titik koma penutup. Kalau kamu menambahkan titik koma di akhir sebuah ekspresi, kamu mengubahnya menjadi statement, dan ia tidak akan lagi mengembalikan nilai. Ingat ini baik-baik saat kita membahas nilai kembalian fungsi dan ekspresi berikutnya.

Fungsi dengan Nilai Kembalian

Fungsi bisa mengembalikan nilai ke kode yang memanggilnya. Kita tidak memberi nama pada nilai kembalian, tapi kita harus mendeklarasikan tipenya setelah tanda panah (->). Di Rust, nilai kembalian sebuah fungsi identik dengan nilai dari ekspresi terakhir di blok badan fungsi itu. Kamu bisa keluar lebih awal dari sebuah fungsi memakai keyword return dan menentukan sebuah nilai, tapi kebanyakan fungsi mengembalikan ekspresi terakhirnya secara implisit. Berikut contoh fungsi yang mengembalikan sebuah nilai:

Nama berkas: src/main.rs

fn five() -> i32 {
    5
}

fn main() {
    let x = five();

    println!("Nilai x adalah: {x}");
}

Tidak ada pemanggilan fungsi, macro, atau bahkan statement let di fungsi five — hanya angka 5 sendirian. Itu fungsi yang sepenuhnya valid di Rust. Perhatikan tipe kembalian fungsi ini juga ditentukan, sebagai -> i32. Coba jalankan kode ini; outputnya seharusnya: 

$ cargo run
   Compiling functions v0.1.0 (file:///projects/functions)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.30s
     Running `target/debug/functions`
Nilai x adalah: 5

Angka 5 di fungsi five adalah nilai kembalian fungsi itu, itulah kenapa tipe kembaliannya i32. Mari periksa lebih detail. Ada dua hal penting: pertama, baris let x = five(); menunjukkan kita memakai nilai kembalian sebuah fungsi untuk menginisialisasi sebuah variabel. Karena fungsi five mengembalikan 5, baris itu sama saja dengan: 

let x = 5;

Kedua, fungsi five tidak punya parameter dan mendefinisikan tipe nilai kembaliannya, tapi badan fungsinya cuma angka 5 sendirian tanpa titik koma karena itu adalah ekspresi yang nilainya ingin kita kembalikan.

Mari lihat contoh lain:

Nama berkas: src/main.rs

fn main() {
    let x = plus_one(5);

    println!("Nilai x adalah: {x}");
}

fn plus_one(x: i32) -> i32 {
    x + 1
}

Menjalankan kode ini akan mencetak Nilai x adalah: 6. Tapi apa yang terjadi kalau kita taruh titik koma di akhir baris berisi x + 1, mengubahnya dari ekspresi menjadi statement?

❌ Belum bisa dikompilasi

Nama berkas: src/main.rs

fn main() {
    let x = plus_one(5);

    println!("Nilai x adalah: {x}");
}

fn plus_one(x: i32) -> i32 {
    x + 1;
}

Mengompilasi kode ini akan menghasilkan error:

$ cargo run
   Compiling functions v0.1.0 (file:///projects/functions)
error[E0308]: mismatched types
 --> src/main.rs:7:24
  |
7 | fn plus_one(x: i32) -> i32 {
  |    --------            ^^^ expected `i32`, found `()`
  |    |
  |    implicitly returns `()` as its body has no tail or `return` expression
8 |     x + 1;
  |          - help: remove this semicolon to return this value

For more information about this error, try `rustc --explain E0308`.
error: could not compile `functions` (bin "functions") due to 1 previous error

Pesan error utama, mismatched types, mengungkap inti masalah kode ini. Definisi fungsi plus_one mengatakan ia akan mengembalikan i32, tapi statement tidak dievaluasi menjadi nilai apa pun, yang diekspresikan dengan (), tipe unit. Karena itu, tidak ada yang dikembalikan, yang bertentangan dengan definisi fungsinya dan menghasilkan error. Di output ini, Rust memberi pesan yang mungkin membantu memperbaiki masalah ini: ia menyarankan menghapus titik koma, yang akan memperbaiki errornya.

Fungsi berikut punya bug. Apa yang salah?
fn tambah_satu(x: i32) -> i32 { x + 1; }

Ringkasan

  • Fungsi didefinisikan dengan fn, nama snake_case, dan tipe setiap parameter wajib dianotasi.
  • Statement tidak mengembalikan nilai; ekspresi mengembalikan nilai. Blok { } juga ekspresi.
  • Nilai kembalian fungsi = nilai ekspresi terakhir di badannya (tanpa titik koma), atau lewat return eksplisit.
  • Menambahkan titik koma ke ekspresi terakhir mengubahnya jadi statement bernilai () — penyebab umum error mismatched types.
