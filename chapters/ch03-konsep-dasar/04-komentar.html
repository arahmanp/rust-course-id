Bab 3.4

Komentar

Semua programmer berusaha membuat kodenya mudah dipahami, tapi kadang penjelasan tambahan tetap dibutuhkan. Dalam kasus seperti itu, programmer meninggalkan komentar di source code-nya — yang diabaikan compiler, tapi bisa berguna bagi orang yang membaca source code itu.

Berikut contoh komentar sederhana:

// hello, world

Di Rust, gaya komentar yang idiomatis dimulai dengan dua garis miring (//), dan komentarnya berlanjut sampai akhir baris. Untuk komentar yang lebih dari satu baris, kamu perlu menyertakan // di setiap barisnya, seperti ini: 

// Jadi kita melakukan sesuatu yang rumit di sini, cukup panjang sampai
// kita butuh beberapa baris komentar untuk menjelaskannya! Fiuh, semoga
// komentar ini menjelaskan apa yang sedang terjadi.

Komentar juga bisa diletakkan di akhir baris berisi kode:

Nama berkas: src/main.rs

fn main() {
    let lucky_number = 7; // Aku merasa beruntung hari ini
}

Tapi kamu akan lebih sering melihatnya dipakai dengan format ini, dengan komentar di baris terpisah di atas kode yang dijelaskannya:

Nama berkas: src/main.rs

fn main() {
    // Aku merasa beruntung hari ini
    let lucky_number = 7;
}

ℹ️ Documentation Comments

Rust juga punya jenis komentar lain, documentation comments (diawali /// atau //!), yang dipakai untuk menghasilkan dokumentasi HTML otomatis untuk crate-mu. Kita akan bahas ini di subbab 14.2 (Mempublikasikan Crate ke Crates.io).

Apa yang terjadi pada teks di dalam komentar // saat program dikompilasi?

Ringkasan

  • Komentar satu baris diawali // dan berlaku sampai akhir baris.
  • Komentar multi-baris idiomatisnya tetap mengulang // di setiap baris (Rust juga mengenal komentar blok /* */, tapi jarang dipakai komunitas Rust).
  • Compiler sepenuhnya mengabaikan komentar — murni untuk pembaca manusia.
