Bab 4.3

Tipe Slice

Slice memungkinkanmu merujuk ke sebuah urutan elemen yang berdekatan (contiguous) dalam sebuah koleksi, bukan keseluruhan koleksi itu. Slice adalah semacam referensi, jadi ia tidak punya ownership.

Berikut soal pemrograman kecil: tulis sebuah fungsi yang menerima sebuah string berisi kata-kata dipisah spasi, dan mengembalikan kata pertama yang ditemukan dalam string itu. Kalau fungsi ini tidak menemukan spasi dalam string-nya, seluruh string harus dianggap satu kata, jadi seluruh string itu harus dikembalikan.

ℹ️ Asumsi ASCII

Untuk keperluan memperkenalkan slice, kita asumsikan hanya ASCII di subbab ini; pembahasan lebih menyeluruh soal penanganan UTF-8 ada di subbab 8.2 (Storing UTF-8 Encoded Text with Strings).

Mari kita coba dulu menulis signature fungsi ini tanpa memakai slice, supaya kita paham masalah yang akan diselesaikan slice: 

fn first_word(s: &String) -> ?

Fungsi first_word punya parameter bertipe &String. Kita tidak butuh ownership-nya, jadi ini sudah pas. (Di Rust yang idiomatis, fungsi tidak mengambil ownership argumennya kecuali memang butuh, dan alasannya akan makin jelas seiring kita lanjut.) Tapi apa yang seharusnya kita kembalikan? Kita sebenarnya tidak punya cara membicarakan bagian dari sebuah string. Tapi, kita bisa mengembalikan indeks akhir kata itu, ditandai sebuah spasi. Mari coba, seperti berikut:

Nama berkas: src/main.rs

fn first_word(s: &String) -> usize {
    let bytes = s.as_bytes();

    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return i;
        }
    }

    s.len()
}

Karena kita perlu melewati String elemen demi elemen dan memeriksa apakah sebuah nilai adalah spasi, kita akan mengonversi String kita menjadi array byte memakai method as_bytes. 

let bytes = s.as_bytes();

Selanjutnya, kita buat sebuah iterator di atas array byte itu memakai method iter:

for (i, &item) in bytes.iter().enumerate() {

Kita akan bahas iterator lebih detail di Bab 13. Untuk sekarang, cukup tahu bahwa iter adalah method yang mengembalikan setiap elemen dalam sebuah koleksi, dan enumerate membungkus hasil iter dan mengembalikan setiap elemen sebagai bagian dari sebuah tuple. Elemen pertama dari tuple yang dikembalikan enumerate adalah indeksnya, dan elemen kedua adalah referensi ke elemennya. Ini sedikit lebih praktis daripada menghitung indeksnya sendiri.

Karena method enumerate mengembalikan sebuah tuple, kita bisa memakai pattern untuk men-destructure tuple itu. Kita akan bahas pattern lebih lanjut di Bab 6. Di loop for, kita menentukan sebuah pattern yang punya i untuk indeksnya dan &item untuk satu byte dalam tuple-nya. Karena kita mendapat referensi ke elemennya dari .iter().enumerate(), kita memakai & di pattern-nya.

Di dalam loop for, kita mencari byte yang merepresentasikan spasi memakai sintaks byte literal. Kalau kita menemukan spasi, kita kembalikan posisinya. Kalau tidak, kita kembalikan panjang string-nya memakai s.len(). 

if item == b' ' {
    return i;
}

s.len()

Sekarang kita punya cara mencari tahu indeks akhir kata pertama dalam string, tapi ada masalah. Kita mengembalikan usize sendirian, tapi itu cuma angka yang bermakna dalam konteks &String-nya. Dengan kata lain, karena ini nilai terpisah dari String-nya, tidak ada jaminan ia akan tetap valid di masa depan. Perhatikan program berikut yang memakai fungsi first_word di atas:

Nama berkas: src/main.rs

fn main() {
    let mut s = String::from("hello world");

    let word = first_word(&s); // word akan bernilai 5

    s.clear(); // ini mengosongkan String-nya, membuatnya sama dengan ""

    // word masih bernilai 5 di sini, tapi s sudah tidak punya konten yang
    // bisa dipakai secara bermakna dengan nilai 5 itu, jadi word sekarang
    // sepenuhnya tidak valid!
}

Program ini berhasil dikompilasi tanpa error, dan tetap begitu walaupun kita memakai word setelah memanggil s.clear(). Karena word sama sekali tidak terhubung dengan state s, word tetap berisi nilai 5. Kita bisa memakai nilai 5 itu dengan variabel s untuk mencoba mengekstrak kata pertamanya, tapi ini akan jadi bug karena isi s sudah berubah sejak kita menyimpan 5 di word.

Harus khawatir soal indeks di word menjadi tidak sinkron dengan data di s itu merepotkan dan rawan error! Mengelola indeks-indeks ini bahkan lebih rapuh kalau kita menulis fungsi second_word. Signature-nya harus seperti ini: 

fn second_word(s: &String) -> (usize, usize) {

Sekarang kita melacak indeks awal dan akhir, dan kita punya lebih banyak lagi nilai yang dihitung dari data pada state tertentu tapi sama sekali tidak terikat ke state itu. Kita punya tiga variabel tidak berhubungan yang mengambang dan harus dijaga tetap sinkron.

Untungnya, Rust punya solusi untuk masalah ini: string slice.

String Slice

String slice adalah referensi ke urutan elemen yang berdekatan dari sebuah String, dan terlihat seperti ini: 

let s = String::from("hello world");

let hello = &s[0..5];
let world = &s[6..11];

Alih-alih referensi ke seluruh String, hello adalah referensi ke sebagian String, ditentukan lewat bagian tambahan [0..5]. Kita membuat slice memakai sebuah range di dalam kurung siku dengan menentukan [starting_index..ending_index], di mana starting_index adalah posisi pertama dalam slice-nya dan ending_index adalah satu lebih dari posisi terakhir dalam slice-nya. Secara internal, struktur data slice menyimpan posisi awal dan panjang slice-nya, yang sama dengan ending_index dikurangi starting_index. Jadi, untuk let world = &s[6..11];, world akan jadi slice yang berisi pointer ke byte di indeks 6 dari s dengan nilai panjang 5.

Dengan sintaks range .. Rust, kalau kamu ingin mulai dari indeks 0, kamu bisa menghilangkan nilai sebelum dua titiknya. Dengan kata lain, ini setara: 

let s = String::from("hello");

let slice = &s[0..2];
let slice = &s[..2];

Dengan logika yang sama, kalau slice-mu menyertakan byte terakhir dari String-nya, kamu bisa menghilangkan angka di belakangnya. Artinya ini setara: 

let s = String::from("hello");

let len = s.len();

let slice = &s[3..len];
let slice = &s[3..];

Kamu juga bisa menghilangkan kedua nilainya untuk mengambil slice dari keseluruhan string. Jadi, ini setara:

let s = String::from("hello");

let len = s.len();

let slice = &s[0..len];
let slice = &s[..];

⚠️ Batas karakter UTF-8

Indeks range string slice harus berada di batas karakter UTF-8 yang valid. Kalau kamu mencoba membuat string slice di tengah-tengah karakter multi-byte, programmu akan keluar dengan error.

Dengan semua informasi ini, mari kita tulis ulang first_word supaya mengembalikan sebuah slice. Tipe yang menandakan "string slice" ditulis sebagai &str:

Nama berkas: src/main.rs

fn first_word(s: &String) -> &str {
    let bytes = s.as_bytes();

    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return &s[0..i];
        }
    }

    &s[..]
}

Kita mendapat indeks akhir katanya dengan cara yang sama seperti sebelumnya, dengan mencari kemunculan spasi pertama. Ketika kita menemukan spasi, kita kembalikan sebuah string slice memakai awal string-nya dan indeks spasinya sebagai indeks awal dan akhir.

Sekarang ketika kita memanggil first_word, kita mendapat satu nilai yang terikat ke data aslinya. Nilai itu tersusun dari sebuah referensi ke titik awal slice-nya dan jumlah elemen dalam slice itu.

Mengembalikan slice juga akan bekerja untuk fungsi second_word:

fn second_word(s: &String) -> &str {

Sekarang kita punya API yang jauh lebih sulit dikacaukan, karena compiler akan memastikan referensi ke String-nya tetap valid. Ingat bug di program sebelumnya, ketika kita mendapat indeks akhir kata pertama tapi kemudian mengosongkan string-nya sehingga indeks kita jadi tidak valid? Kode itu secara logis salah tapi tidak menunjukkan error langsung. Masalahnya baru muncul kemudian kalau kita terus mencoba memakai indeks kata pertama itu dengan string yang sudah dikosongkan. Slice membuat bug ini mustahil terjadi dan memberi tahu kita jauh lebih cepat kalau ada masalah dengan kode kita. Memakai versi slice dari first_word akan melempar error compile-time:

❌ Belum bisa dikompilasi

Nama berkas: src/main.rs

fn main() {
    let mut s = String::from("hello world");

    let word = first_word(&s);

    s.clear(); // error!

    println!("the first word is: {word}");
}

Berikut error compiler-nya:

$ cargo run
   Compiling ownership v0.1.0 (file:///projects/ownership)
error[E0502]: cannot borrow `s` as mutable because it is also borrowed as immutable
  --> src/main.rs:18:5
   |
16 |     let word = first_word(&s);
   |                           -- immutable borrow occurs here
17 |
18 |     s.clear(); // error!
   |     ^^^^^^^^^ mutable borrow occurs here
19 |
20 |     println!("the first word is: {word}");
   |                                   ---- immutable borrow later used here

For more information about this error, try `rustc --explain E0502`.
error: could not compile `ownership` (bin "ownership") due to 1 previous error

Ingat dari aturan borrowing: kalau kita punya immutable reference ke sesuatu, kita tidak boleh juga mengambil mutable reference. Karena clear perlu mengosongkan (truncate) String-nya, ia butuh mutable reference. println! setelah pemanggilan clear memakai referensi di word, jadi immutable reference-nya harus masih aktif di titik itu. Rust melarang mutable reference di clear dan immutable reference di word ada bersamaan pada saat yang sama, dan kompilasinya gagal. Rust tidak cuma membuat API kita lebih mudah dipakai, tapi juga menghilangkan seluruh kelas error ini saat compile-time!

String Literal sebagai Slice

Ingat kita membahas bahwa string literal disimpan di dalam binary. Sekarang kita sudah tahu tentang slice, kita bisa memahami string literal dengan lebih tepat:

let s = "Hello, world!";

Tipe s di sini adalah &str: ini adalah slice yang menunjuk ke titik tertentu di binary-nya. Ini juga kenapa string literal bersifat immutable — &str adalah referensi yang immutable.

String Slice sebagai Parameter

Mengetahui bahwa kamu bisa mengambil slice dari literal maupun nilai String mengarahkan kita ke satu penyempurnaan lagi untuk first_word, yaitu signature-nya: 

fn first_word(s: &String) -> &str {

Rustacean yang lebih berpengalaman akan menulis signature berikut alih-alih, karena ini memungkinkan kita memakai fungsi yang sama baik pada nilai &String maupun &str: 

fn first_word(s: &str) -> &str {
    let bytes = s.as_bytes();

    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return &s[0..i];
        }
    }

    &s[..]
}

Kalau kita punya string slice, kita bisa mengopernya langsung. Kalau kita punya String, kita bisa mengoper sebuah slice dari String itu atau referensi ke String-nya. Fleksibilitas ini memanfaatkan deref coercion, fitur yang akan kita bahas di Bab 15.

Mendefinisikan sebuah fungsi untuk menerima string slice alih-alih referensi ke String membuat API kita lebih umum dan berguna tanpa kehilangan fungsionalitas apa pun:

Nama berkas: src/main.rs

fn main() {
    let my_string = String::from("hello world");

    // `first_word` bekerja pada slice dari `String`, baik sebagian maupun utuh.
    let word = first_word(&my_string[0..6]);
    let word = first_word(&my_string[..]);
    // `first_word` juga bekerja pada referensi ke `String`, yang setara
    // dengan slice utuh dari `String`.
    let word = first_word(&my_string);

    let my_string_literal = "hello world";

    // `first_word` bekerja pada slice dari string literal, baik sebagian
    // maupun utuh.
    let word = first_word(&my_string_literal[0..6]);
    let word = first_word(&my_string_literal[..]);

    // Karena string literal itu *sudah* string slice,
    // ini juga bekerja, tanpa perlu sintaks slice sama sekali!
    let word = first_word(my_string_literal);
}

Slice Lainnya

String slice, seperti bisa kamu bayangkan, khusus untuk string. Tapi ada juga tipe slice yang lebih umum. Perhatikan array berikut: 

let a = [1, 2, 3, 4, 5];

Sama seperti kita mungkin ingin merujuk ke sebagian string, kita mungkin juga ingin merujuk ke sebagian array. Kita bisa melakukannya seperti ini: 

let a = [1, 2, 3, 4, 5];

let slice = &a[1..3];

assert_eq!(slice, &[2, 3]);

Slice ini bertipe &[i32]. Cara kerjanya sama seperti string slice, dengan menyimpan referensi ke elemen pertama dan sebuah panjang. Kamu akan memakai jenis slice ini untuk segala macam koleksi lainnya. Kita akan bahas koleksi ini lebih detail saat membahas vector di Bab 8.

Kenapa versi first_word yang mengembalikan &str (slice) lebih aman daripada versi yang mengembalikan usize (indeks)?

Ringkasan Bab 4

  • Slice (&str untuk string, &[T] untuk koleksi lain) adalah referensi ke sebagian data berdekatan — tidak punya ownership, dan terikat aturan borrowing seperti referensi biasa.
  • Lebih suka menulis parameter fungsi bertipe &str daripada &String supaya fungsimu bekerja untuk string literal maupun String.
  • Konsep ownership, borrowing, dan slice bersama-sama menjamin keamanan memori Rust saat compile-time, tanpa garbage collector dan tanpa overhead runtime.

Ownership memengaruhi cara kerja banyak bagian lain Rust, jadi kita akan membahas konsep-konsep ini lebih jauh sepanjang sisa buku ini. Mari lanjut ke Bab 5 dan lihat cara mengelompokkan data ke dalam sebuah struct.
