Bab 5.1

Mendefinisikan dan Membuat Instance Struct

Struct mirip dengan tuple yang kita bahas di subbab 3.2, dalam artian keduanya menampung banyak nilai yang saling terkait. Seperti tuple, bagian-bagian dalam struct bisa bertipe berbeda-beda. Berbeda dari tuple, di struct kamu memberi nama pada setiap bagian datanya, sehingga jelas apa makna nilai-nilai itu. Menambahkan nama-nama ini membuat struct lebih fleksibel daripada tuple: kamu tidak perlu bergantung pada urutan data untuk menentukan atau mengakses nilai sebuah instance.

Untuk mendefinisikan sebuah struct, kita ketik keyword struct dan beri nama seluruh struct-nya. Nama struct harus menggambarkan makna dari data-data yang dikelompokkan bersama. Lalu, di dalam kurung kurawal, kita definisikan nama dan tipe data-data itu, yang kita sebut field. Misalnya, berikut struct yang menyimpan informasi akun pengguna:

Nama berkas: src/main.rs

struct User {
    active: bool,
    username: String,
    email: String,
    sign_in_count: u64,
}

Untuk memakai struct setelah kita mendefinisikannya, kita buat sebuah instance dari struct itu dengan menentukan nilai konkret untuk setiap field-nya. Kita membuat instance dengan menyebutkan nama struct-nya, lalu menambahkan kurung kurawal berisi pasangan key: value, di mana key-nya adalah nama field dan value-nya adalah data yang ingin kita simpan di field itu. Kita tidak harus menentukan field dengan urutan yang sama seperti saat kita mendeklarasikannya di struct-nya. Dengan kata lain, definisi struct itu seperti sebuah template umum untuk tipenya, dan instance-instance mengisi template itu dengan data tertentu untuk membuat nilai bertipe itu. Misalnya, kita bisa mendeklarasikan seorang pengguna tertentu seperti ini:

Nama berkas: src/main.rs

fn main() {
    let user1 = User {
        active: true,
        username: String::from("someusername123"),
        email: String::from("someone@example.com"),
        sign_in_count: 1,
    };
}

Untuk mendapatkan sebuah nilai tertentu dari struct, kita memakai notasi titik. Misalnya, untuk mengakses alamat email pengguna ini, kita pakai user1.email. Kalau instance-nya mutable, kita bisa mengubah sebuah nilai dengan notasi titik dan menetapkannya ke field tertentu. Berikut cara mengubah nilai field email dari instance User yang mutable:

Nama berkas: src/main.rs

fn main() {
    let mut user1 = User {
        active: true,
        username: String::from("someusername123"),
        email: String::from("someone@example.com"),
        sign_in_count: 1,
    };

    user1.email = String::from("anotheremail@example.com");
}

⚠️ Seluruh instance harus mutable

Perhatikan seluruh instance-nya harus mutable; Rust tidak mengizinkan kita menandai hanya field tertentu saja sebagai mutable.

Seperti ekspresi lainnya, kita bisa membuat instance baru dari struct sebagai ekspresi terakhir di badan fungsi untuk secara implisit mengembalikan instance baru itu.

Berikut fungsi build_user yang mengembalikan sebuah instance User dengan email dan username yang diberikan. Field active mendapat nilai true, dan sign_in_count mendapat nilai 1.

Nama berkas: src/main.rs

fn build_user(email: String, username: String) -> User {
    User {
        active: true,
        username: username,
        email: email,
        sign_in_count: 1,
    }
}

Masuk akal memberi nama parameter fungsi sama seperti nama field struct-nya, tapi harus mengulang nama field email dan username beserta variabelnya sedikit merepotkan. Kalau struct-nya punya lebih banyak field, mengulang setiap nama akan makin menjengkelkan. Untungnya, ada singkatan yang praktis!

Memakai Field Init Shorthand

Karena nama parameter dan nama field struct-nya persis sama di contoh sebelumnya, kita bisa memakai sintaks field init shorthand untuk menulis ulang build_user supaya perilakunya persis sama tapi tanpa pengulangan username dan email:

Nama berkas: src/main.rs

fn build_user(email: String, username: String) -> User {
    User {
        active: true,
        username,
        email,
        sign_in_count: 1,
    }
}

Di sini, kita membuat instance baru dari struct User, yang punya field bernama email. Kita ingin men-set nilai field email ke nilai parameter email di fungsi build_user. Karena field email dan parameter email punya nama yang sama, kita cukup menulis email, bukan email: email.

Membuat Instance dengan Struct Update Syntax

Sering kali berguna untuk membuat instance baru dari sebuah struct yang menyertakan sebagian besar nilai dari instance lain bertipe sama, tapi mengubah sebagian nilainya. Kamu bisa melakukan ini memakai struct update syntax.

Pertama, berikut cara membuat instance User baru di user2 dengan cara biasa, tanpa update syntax. Kita set nilai baru untuk email tapi selebihnya memakai nilai yang sama dari user1:

Nama berkas: src/main.rs

let user2 = User {
    active: user1.active,
    username: user1.username,
    email: String::from("another@example.com"),
    sign_in_count: user1.sign_in_count,
};

Memakai struct update syntax, kita bisa mencapai efek yang sama dengan kode lebih sedikit. Sintaks .. menentukan bahwa field-field yang tersisa dan tidak diset secara eksplisit akan punya nilai sama seperti field di instance yang diberikan.

Nama berkas: src/main.rs

let user2 = User {
    email: String::from("another@example.com"),
    ..user1
};

Kode ini juga membuat instance di user2 yang punya nilai berbeda untuk email tapi nilai yang sama untuk field username, active, dan sign_in_count dari user1. Bagian ..user1 harus diletakkan paling akhir untuk menentukan bahwa field-field yang tersisa harus mengambil nilainya dari field yang sesuai di user1, tapi kita bisa memilih menentukan nilai untuk sebanyak apa pun field, dengan urutan apa pun, terlepas dari urutan field di definisi struct-nya.

⚠️ Struct update syntax memakai move

Perhatikan struct update syntax memakai = seperti assignment; ini karena ia memindahkan (move) datanya, sama seperti yang kita lihat di subbab 4.1 (Variabel dan Data Berinteraksi lewat Move). Di contoh ini, kita sudah tidak bisa lagi memakai user1 setelah membuat user2 karena String di field username milik user1 sudah di-move ke user2. Kalau kita memberi user2 nilai String baru untuk email maupun username, sehingga hanya memakai nilai active dan sign_in_count dari user1, maka user1 akan tetap valid setelah user2 dibuat. Baik active maupun sign_in_count adalah tipe yang mengimplementasikan trait Copy, jadi perilaku yang kita bahas di subbab 4.1 (Data Stack Saja: Trait Copy) berlaku di sini. Kita juga masih bisa memakai user1.email di contoh ini, karena nilainya tidak ikut di-move keluar dari user1.

Membuat Tipe Berbeda dengan Tuple Struct

Rust juga mendukung struct yang terlihat mirip tuple, disebut tuple struct. Tuple struct punya makna tambahan yang diberikan nama struct-nya, tapi tidak punya nama yang terasosiasi dengan field-fieldnya — field-fieldnya hanya punya tipe. Tuple struct berguna ketika kamu ingin memberi nama pada seluruh tuple dan menjadikan tuple itu tipe yang berbeda dari tuple lain, dan ketika memberi nama tiap field seperti struct biasa akan terasa bertele-tele atau redundan.

Untuk mendefinisikan tuple struct, mulai dengan keyword struct dan nama struct-nya diikuti tipe-tipe di dalam tuple-nya. Misalnya, berikut kita definisikan dan pakai dua tuple struct bernama Color dan Point:

Nama berkas: src/main.rs

struct Color(i32, i32, i32);
struct Point(i32, i32, i32);

fn main() {
    let black = Color(0, 0, 0);
    let origin = Point(0, 0, 0);
}

Perhatikan nilai black dan origin bertipe berbeda, karena keduanya instance dari tuple struct yang berbeda. Setiap struct yang kamu definisikan adalah tipenya sendiri, walaupun field-field di dalam struct itu mungkin bertipe sama. Misalnya, sebuah fungsi yang menerima parameter bertipe Color tidak bisa menerima Point sebagai argumen, walaupun kedua tipe itu sama-sama tersusun dari tiga nilai i32. Selebihnya, instance tuple struct mirip tuple biasa — kamu bisa men-destructure-nya menjadi bagian-bagiannya, dan bisa memakai . diikuti indeks untuk mengakses nilai tertentu. Berbeda dari tuple, tuple struct mengharuskanmu menyebut nama tipe struct-nya saat men-destructure. Misalnya, kita akan menulis let Point(x, y, z) = origin; untuk men-destructure nilai di origin menjadi variabel x, y, dan z.

Mendefinisikan Unit-Like Struct

Kamu juga bisa mendefinisikan struct yang tidak punya field sama sekali! Ini disebut unit-like struct karena perilakunya mirip (), tipe unit yang kita bahas di subbab 3.2. Unit-like struct bisa berguna ketika kamu perlu mengimplementasikan sebuah trait pada suatu tipe tapi tidak punya data apa pun yang ingin kamu simpan di tipe itu sendiri. Kita akan bahas trait di Bab 10. Berikut contoh mendeklarasikan dan membuat instance unit struct bernama AlwaysEqual:

Nama berkas: src/main.rs

struct AlwaysEqual;

fn main() {
    let subject = AlwaysEqual;
}

Untuk mendefinisikan AlwaysEqual, kita pakai keyword struct, nama yang kita inginkan, lalu titik koma. Tidak perlu kurung kurawal atau kurung biasa! Lalu, kita bisa mendapat instance AlwaysEqual di variabel subject dengan cara serupa: memakai nama yang sudah kita definisikan, tanpa kurung kurawal atau kurung biasa apa pun. Bayangkan nanti kita akan mengimplementasikan perilaku untuk tipe ini sehingga setiap instance AlwaysEqual selalu sama dengan instance dari tipe apa pun lainnya, mungkin untuk mendapat hasil yang sudah diketahui untuk keperluan testing. Kita tidak akan butuh data apa pun untuk mengimplementasikan perilaku itu! Kamu akan lihat di Bab 10 cara mendefinisikan trait dan mengimplementasikannya pada tipe apa pun, termasuk unit-like struct.

ℹ️ Ownership Data Struct

Di definisi struct User sebelumnya, kita memakai tipe String yang owned, bukan tipe string slice &str. Ini pilihan yang disengaja karena kita ingin setiap instance struct ini memiliki (own) seluruh datanya sendiri, dan data itu valid selama seluruh struct-nya valid.

Struct juga bisa menyimpan referensi ke data yang dimiliki sesuatu yang lain, tapi untuk itu dibutuhkan lifetime, sebuah fitur Rust yang akan kita bahas di Bab 10. Lifetime memastikan data yang direferensikan sebuah struct tetap valid selama struct itu valid. Misalkan kamu coba menyimpan sebuah referensi dalam struct tanpa menentukan lifetime, seperti berikut — ini tidak akan bekerja:

❌ Belum bisa dikompilasi
struct User {
    active: bool,
    username: &str,
    email: &str,
    sign_in_count: u64,
}

fn main() {
    let user1 = User {
        active: true,
        username: "someusername123",
        email: "someone@example.com",
        sign_in_count: 1,
    };
}

Di Bab 10, kita akan bahas cara memperbaiki error ini supaya kamu bisa menyimpan referensi di dalam struct, tapi untuk sekarang, kita akan memperbaiki error semacam ini dengan memakai tipe owned seperti String, bukan referensi seperti &str.

Kenapa let user2 = User { email: String::from("..."), ..user1 }; membuat user1 tidak valid lagi setelahnya?

Ringkasan

  • Struct mengelompokkan data terkait dengan memberi nama pada setiap field — lebih jelas daripada tuple.
  • Field init shorthand: kalau nama parameter/variabel sama dengan nama field, cukup tulis field alih-alih field: field.
  • Struct update syntax ..instance_lama mengisi field yang tidak disebutkan dari instance lain — bisa memicu move pada field yang bukan Copy.
  • Tuple struct (struct Color(i32, i32, i32);) memberi nama tipe pada tuple tanpa menamai field-nya.
  • Unit-like struct (struct AlwaysEqual;) tidak punya field sama sekali — berguna untuk mengimplementasikan trait tanpa data.
