Bab 5.2

Contoh Program Menggunakan Struct

Untuk memahami kapan kita mungkin ingin memakai struct, mari tulis program yang menghitung luas sebuah persegi panjang. Kita akan mulai memakai variabel tunggal, lalu me-refactor programnya sampai akhirnya memakai struct.

Mari buat proyek binary baru dengan Cargo bernama rectangles yang akan menerima lebar dan tinggi sebuah persegi panjang dalam pixel dan menghitung luasnya. Berikut program singkat dengan salah satu cara melakukannya, di src/main.rs:

Nama berkas: src/main.rs

fn main() {
    let width1 = 30;
    let height1 = 50;

    println!(
        "Luas persegi panjangnya adalah {} pixel persegi.",
        area(width1, height1)
    );
}

fn area(width: u32, height: u32) -> u32 {
    width * height
}

Sekarang, jalankan program ini dengan cargo run:

$ cargo run
   Compiling rectangles v0.1.0 (file:///projects/rectangles)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.42s
     Running `target/debug/rectangles`
Luas persegi panjangnya adalah 1500 pixel persegi.

Kode ini berhasil menghitung luas persegi panjangnya dengan memanggil fungsi area dengan masing-masing dimensi, tapi kita bisa membuat kode ini lebih jelas dan mudah dibaca.

Masalah kode ini terlihat jelas di signature area:

fn area(width: u32, height: u32) -> u32 {

Fungsi area seharusnya menghitung luas satu persegi panjang, tapi fungsi yang kita tulis punya dua parameter, dan tidak ada satu pun bagian program kita yang menunjukkan bahwa kedua parameter itu saling terkait. Akan lebih mudah dibaca dan dikelola kalau kita mengelompokkan lebar dan tinggi bersama-sama. Kita sudah membahas satu cara melakukannya di subbab 3.2: memakai tuple.

Refactor Memakai Tuple

Berikut versi lain program kita yang memakai tuple:

Nama berkas: src/main.rs

fn main() {
    let rect1 = (30, 50);

    println!(
        "Luas persegi panjangnya adalah {} pixel persegi.",
        area(rect1)
    );
}

fn area(dimensions: (u32, u32)) -> u32 {
    dimensions.0 * dimensions.1
}

Di satu sisi, program ini lebih baik. Tuple memungkinkan kita menambahkan sedikit struktur, dan sekarang kita cuma mengoper satu argumen. Tapi di sisi lain, versi ini kurang jelas: tuple tidak memberi nama pada elemen-elemennya, jadi kita harus mengindeks ke bagian-bagian tuple-nya, membuat perhitungan kita jadi kurang gamblang.

Menukar lebar dan tinggi tidak akan jadi masalah untuk perhitungan luasnya, tapi kalau kita ingin menggambar persegi panjangnya di layar, itu akan jadi masalah! Kita harus ingat bahwa width adalah indeks tuple 0 dan height adalah indeks tuple 1. Ini akan makin sulit bagi orang lain untuk memahami dan mengingatnya kalau mereka memakai kode kita. Karena kita tidak menyampaikan makna data kita di dalam kode, sekarang jadi lebih mudah memasukkan error.

Refactor Memakai Struct: Menambah Makna

Kita memakai struct untuk menambah makna dengan memberi label pada data. Kita bisa mengubah tuple yang kita pakai menjadi struct dengan nama untuk keseluruhannya sekaligus nama untuk bagian-bagiannya:

Nama berkas: src/main.rs

struct Rectangle {
    width: u32,
    height: u32,
}

fn main() {
    let rect1 = Rectangle {
        width: 30,
        height: 50,
    };

    println!(
        "Luas persegi panjangnya adalah {} pixel persegi.",
        area(&rect1)
    );
}

fn area(rectangle: &Rectangle) -> u32 {
    rectangle.width * rectangle.height
}

Di sini, kita mendefinisikan sebuah struct dan menamainya Rectangle. Di dalam kurung kurawal, kita definisikan field-nya sebagai width dan height, keduanya bertipe u32. Lalu, di main, kita buat sebuah instance Rectangle tertentu dengan lebar 30 dan tinggi 50.

Fungsi area kita sekarang didefinisikan dengan satu parameter, yang kita namai rectangle, bertipe immutable borrow dari sebuah instance struct Rectangle. Seperti disinggung di Bab 4, kita ingin meminjam struct-nya, bukan mengambil ownership-nya. Dengan cara ini, main tetap memegang ownership-nya dan bisa terus memakai rect1, itulah alasan kita memakai & di signature fungsi dan di titik pemanggilannya.

Fungsi area mengakses field width dan height dari instance Rectangle-nya (perhatikan mengakses field dari instance struct yang dipinjam tidak memindahkan nilai field-nya, itulah kenapa kamu sering melihat struct dipinjam). Signature fungsi area kita sekarang mengatakan persis apa yang kita maksud: menghitung luas Rectangle, memakai field width dan height-nya. Ini menyampaikan bahwa lebar dan tinggi saling terkait satu sama lain, dan memberi nama yang deskriptif pada nilai-nilai itu daripada memakai nilai indeks tuple 0 dan 1. Ini kemenangan untuk kejelasan kode.

Menambah Fungsionalitas dengan Derived Trait

Akan berguna kalau kita bisa mencetak instance Rectangle selagi kita men-debug program kita, untuk melihat nilai semua field-nya. Berikut kita coba memakai macro println! seperti yang sudah kita pakai di bab-bab sebelumnya. Tapi ini tidak akan bekerja.

❌ Belum bisa dikompilasi

Nama berkas: src/main.rs

struct Rectangle {
    width: u32,
    height: u32,
}

fn main() {
    let rect1 = Rectangle {
        width: 30,
        height: 50,
    };

    println!("rect1 is {rect1}");
}

Ketika kita kompilasi kode ini, kita dapat error dengan pesan inti:

error[E0277]: `Rectangle` doesn't implement `std::fmt::Display`

Macro println! bisa melakukan banyak jenis formatting, dan secara default, kurung kurawal memberi tahu println! memakai format yang dikenal sebagai Display: output yang dirancang untuk langsung dikonsumsi pengguna akhir. Tipe primitif yang sudah kita lihat sejauh ini mengimplementasikan Display secara default karena hanya ada satu cara kamu ingin menampilkan 1 atau tipe primitif lain ke pengguna. Tapi dengan struct, cara println! harus memformat outputnya kurang jelas karena ada lebih banyak kemungkinan tampilan: apakah kamu ingin koma atau tidak? Apakah kamu ingin mencetak kurung kurawalnya? Haruskah semua field ditampilkan? Karena ambiguitas ini, Rust tidak mencoba menebak apa yang kita mau, dan struct tidak punya implementasi Display bawaan untuk dipakai dengan println! dan placeholder {}.

Kalau kita terus membaca errornya, kita akan menemukan catatan berguna ini:

= note: in format strings you may be able to use `{:?}` (or {:#?} for pretty-print) instead

Mari coba! Pemanggilan macro println! sekarang akan terlihat seperti println!("rect1 is {rect1:?}");. Menaruh specifier :? di dalam kurung kurawal memberi tahu println! kita ingin memakai format output bernama Debug. Trait Debug memungkinkan kita mencetak struct kita dengan cara yang berguna untuk developer, supaya kita bisa melihat nilainya selagi men-debug kode kita.

Kompilasi kode dengan perubahan ini. Yah! Kita masih dapat error:

error[E0277]: `Rectangle` doesn't implement `Debug`

Tapi lagi-lagi, compiler memberi kita catatan yang berguna:

help: consider annotating `Rectangle` with `#[derive(Debug)]`

Rust memang menyertakan fungsionalitas untuk mencetak informasi debugging, tapi kita harus secara eksplisit opt-in untuk mengaktifkan fungsionalitas itu untuk struct kita. Untuk itu, kita tambahkan outer attribute #[derive(Debug)] persis sebelum definisi struct-nya:

Nama berkas: src/main.rs

#[derive(Debug)]
struct Rectangle {
    width: u32,
    height: u32,
}

fn main() {
    let rect1 = Rectangle {
        width: 30,
        height: 50,
    };

    println!("rect1 is {rect1:?}");
}

Sekarang saat kita jalankan programnya, kita tidak akan dapat error, dan hasilnya:

$ cargo run
   Compiling rectangles v0.1.0 (file:///projects/rectangles)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.48s
     Running `target/debug/rectangles`
rect1 is Rectangle { width: 30, height: 50 }

Bagus! Ini bukan output paling cantik, tapi menunjukkan nilai semua field instance ini, yang tentu akan sangat membantu saat debugging. Kalau struct-nya lebih besar, akan berguna punya output yang sedikit lebih mudah dibaca; untuk kasus itu, kita bisa memakai {:#?} alih-alih {:?} di string println!. Di contoh ini, memakai gaya {:#?} akan menghasilkan: 

$ cargo run
   Compiling rectangles v0.1.0 (file:///projects/rectangles)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.48s
     Running `target/debug/rectangles`
rect1 is Rectangle {
    width: 30,
    height: 50,
}

Cara lain untuk mencetak nilai memakai format Debug adalah memakai macro dbg!, yang mengambil ownership dari sebuah ekspresi (berbeda dari println!, yang mengambil referensi), mencetak nama file dan nomor baris di mana pemanggilan macro dbg! itu terjadi di kodemu beserta nilai hasil ekspresi itu, lalu mengembalikan ownership nilainya.

ℹ️ dbg! mencetak ke stderr

Memanggil macro dbg! mencetak ke standard error console stream (stderr), berbeda dari println!, yang mencetak ke standard output console stream (stdout). Kita akan bahas lebih lanjut soal stderr dan stdout di subbab 12.6.

Berikut contoh di mana kita tertarik pada nilai yang ditetapkan ke field width, sekaligus nilai keseluruhan struct di rect1:

Nama berkas: src/main.rs

#[derive(Debug)]
struct Rectangle {
    width: u32,
    height: u32,
}

fn main() {
    let scale = 2;
    let rect1 = Rectangle {
        width: dbg!(30 * scale),
        height: 50,
    };

    dbg!(&rect1);
}

Kita bisa membungkus dbg! di sekitar ekspresi 30 * scale, dan karena dbg! mengembalikan ownership nilai ekspresinya, field width akan mendapat nilai yang sama seperti kalau kita tidak memanggil dbg! di situ. Kita tidak ingin dbg! mengambil ownership rect1, jadi kita pakai referensi ke rect1 di pemanggilan berikutnya. Berikut tampilan outputnya: 

$ cargo run
   Compiling rectangles v0.1.0 (file:///projects/rectangles)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.61s
     Running `target/debug/rectangles`
[src/main.rs:10:16] 30 * scale = 60
[src/main.rs:14:5] &rect1 = Rectangle {
    width: 60,
    height: 50,
}

Kita bisa lihat bagian output pertama berasal dari src/main.rs baris 10, tempat kita men-debug ekspresi 30 * scale, dan hasilnya adalah 60 (format Debug untuk integer hanya mencetak nilainya saja). Pemanggilan dbg! di baris 14 src/main.rs menampilkan nilai &rect1, yaitu struct Rectangle-nya. Output ini memakai format Debug yang rapi untuk tipe Rectangle. Macro dbg! bisa sangat membantu ketika kamu mencoba mencari tahu apa yang sedang dilakukan kodemu!

Selain trait Debug, Rust sudah menyediakan sejumlah trait yang bisa kita pakai dengan attribute derive yang bisa menambahkan perilaku berguna ke tipe custom kita. Trait-trait itu beserta perilakunya terdaftar di Lampiran C. Kita akan bahas cara mengimplementasikan trait ini dengan perilaku custom, serta cara membuat trait-mu sendiri, di Bab 10. Ada juga banyak attribute selain derive; untuk info lebih lanjut, lihat seksi "Attributes" di Rust Reference.

Fungsi area kita sangat spesifik: ia hanya menghitung luas persegi panjang. Akan berguna kalau kita mengaitkan perilaku ini lebih erat dengan struct Rectangle kita, karena ia memang tidak akan bekerja untuk tipe lain. Mari lihat bagaimana kita bisa melanjutkan me-refactor kode ini dengan mengubah fungsi area menjadi sebuah method area yang didefinisikan pada tipe Rectangle kita.

Kenapa println!("{rect1}") gagal untuk struct Rectangle biasa, padahal bekerja untuk i32 atau String?

Ringkasan

  • Struct membuat kode lebih jelas dibanding tuple/variabel lepas karena setiap bagian data punya nama.
  • #[derive(Debug)] mengaktifkan format {:?} / {:#?} di println! untuk keperluan debugging.
  • Macro dbg! mencetak ke stderr beserta lokasi file:baris, dan mengembalikan ownership nilainya — cocok disisipkan langsung di tengah ekspresi.
