Bab 5.3

Sintaks Method

Method mirip dengan fungsi: kita mendeklarasikannya dengan keyword fn dan sebuah nama, method bisa punya parameter dan nilai kembalian, dan berisi kode yang dijalankan ketika method itu dipanggil dari tempat lain. Berbeda dari fungsi, method didefinisikan dalam konteks sebuah struct (atau enum atau trait object, yang kita bahas di Bab 6 dan Bab 18), dan parameter pertamanya selalu self, yang merepresentasikan instance struct tempat method itu dipanggil.

Sintaks Method

Mari ubah fungsi area yang menerima instance Rectangle sebagai parameter, dan sebagai gantinya buat method area yang didefinisikan pada struct Rectangle:

Nama berkas: src/main.rs

#[derive(Debug)]
struct Rectangle {
    width: u32,
    height: u32,
}

impl Rectangle {
    fn area(&self) -> u32 {
        self.width * self.height
    }
}

fn main() {
    let rect1 = Rectangle {
        width: 30,
        height: 50,
    };

    println!(
        "Luas persegi panjangnya adalah {} pixel persegi.",
        rect1.area()
    );
}

Untuk mendefinisikan fungsi dalam konteks Rectangle, kita mulai blok impl (implementation) untuk Rectangle. Semua yang ada di dalam blok impl ini akan diasosiasikan dengan tipe Rectangle. Lalu, kita pindahkan fungsi area ke dalam kurung kurawal impl dan ubah parameter pertama (dan dalam kasus ini, satu-satunya) menjadi self di signature-nya dan di mana pun di badan fungsinya. Di main, tempat kita dulu memanggil fungsi area dan mengoper rect1 sebagai argumen, sekarang kita bisa memakai sintaks method untuk memanggil method area pada instance Rectangle kita. Sintaks method diletakkan setelah sebuah instance: kita tambahkan titik diikuti nama method-nya, tanda kurung, dan argumen apa pun.

Di signature area, kita pakai &self alih-alih rectangle: &Rectangle. &self sebenarnya singkatan dari self: &Self. Di dalam blok impl, tipe Self adalah alias untuk tipe tempat blok impl itu berada. Method harus punya parameter bernama self bertipe Self sebagai parameter pertamanya, jadi Rust mengizinkanmu menyingkatnya cukup dengan nama self di posisi parameter pertama. Perhatikan kita tetap perlu memakai & di depan singkatan self untuk menandakan method ini meminjam instance Self-nya, persis seperti yang kita lakukan di rectangle: &Rectangle. Method bisa mengambil ownership self, meminjam self secara immutable seperti yang kita lakukan di sini, atau meminjam self secara mutable, sama seperti parameter lain mana pun.

Kita memilih &self di sini dengan alasan sama seperti kita memakai &Rectangle di versi fungsinya: kita tidak ingin mengambil ownership-nya, kita cuma ingin membaca data di struct-nya, bukan menulis ke situ. Kalau kita ingin mengubah instance yang dipanggil method-nya sebagai bagian dari apa yang dilakukan method itu, kita akan pakai &mut self sebagai parameter pertamanya. Punya method yang mengambil ownership instance-nya cukup dengan memakai self saja sebagai parameter pertama jarang terjadi; teknik ini biasanya dipakai ketika method-nya mentransformasikan self menjadi sesuatu yang lain dan kamu ingin mencegah si pemanggil memakai instance aslinya lagi setelah transformasi itu.

Alasan utama memakai method daripada fungsi, selain menyediakan sintaks method dan tidak perlu mengulang tipe self di setiap signature method, adalah untuk organisasi. Kita menaruh semua hal yang bisa kita lakukan dengan instance sebuah tipe di satu blok impl, alih-alih membuat pengguna kode kita di masa depan mencari kemampuan Rectangle di berbagai tempat berbeda dalam library yang kita sediakan.

Perhatikan kita bisa memilih memberi sebuah method nama yang sama dengan salah satu field struct-nya. Misalnya, kita bisa mendefinisikan method pada Rectangle yang juga bernama width:

Nama berkas: src/main.rs

impl Rectangle {
    fn width(&self) -> bool {
        self.width > 0
    }
}

fn main() {
    let rect1 = Rectangle {
        width: 30,
        height: 50,
    };

    if rect1.width() {
        println!("Persegi panjangnya punya lebar bukan-nol; lebarnya {}", rect1.width);
    }
}

Di sini, kita memilih membuat method width mengembalikan true kalau nilai di field width instance-nya lebih besar dari 0, dan false kalau nilainya 0: kita bisa memakai field dengan nama sama di dalam sebuah method untuk tujuan apa pun. Di main, ketika kita mengikuti rect1.width dengan tanda kurung, Rust tahu kita maksudnya method width. Ketika kita tidak memakai tanda kurung, Rust tahu kita maksudnya field width.

Sering kali, tapi tidak selalu, ketika kita memberi sebuah method nama yang sama dengan sebuah field, kita ingin method itu hanya mengembalikan nilai di field-nya dan tidak melakukan apa pun yang lain. Method seperti ini disebut getter, dan Rust tidak otomatis mengimplementasikannya untuk field struct seperti yang dilakukan beberapa bahasa lain. Getter berguna karena kamu bisa membuat field-nya private tapi method-nya public, sehingga memungkinkan akses read-only ke field itu sebagai bagian dari public API tipe tersebut. Kita akan bahas apa itu public dan private, serta cara menentukan sebuah field atau method sebagai public atau private, di Bab 7.

ℹ️ Ke mana perginya operator ->?

Di C dan C++, ada dua operator berbeda yang dipakai untuk memanggil method: kamu pakai . kalau memanggil method langsung pada objeknya, dan -> kalau memanggil method pada pointer ke objek itu dan perlu men-dereference pointer-nya lebih dulu. Dengan kata lain, kalau object adalah sebuah pointer, object->something() mirip dengan (*object).something().

Rust tidak punya operator setara ->; sebagai gantinya, Rust punya fitur bernama automatic referencing and dereferencing. Memanggil method adalah salah satu dari sedikit tempat di Rust dengan perilaku ini.

Begini cara kerjanya: ketika kamu memanggil method dengan object.something(), Rust otomatis menambahkan &, &mut, atau * supaya object cocok dengan signature method-nya. Dengan kata lain, berikut ini sama: 

p1.distance(&p2);
(&p1).distance(&p2);

Yang pertama terlihat jauh lebih rapi. Perilaku automatic referencing ini bekerja karena method punya penerima (receiver) yang jelas — yaitu tipe self-nya. Dengan mengetahui penerima dan nama sebuah method, Rust bisa memastikan dengan pasti apakah method itu membaca (&self), mengubah (&mut self), atau mengonsumsi (self). Fakta bahwa Rust membuat borrowing implisit untuk penerima method adalah bagian besar dari apa yang membuat ownership terasa ergonomis di praktiknya.

Method dengan Parameter Lebih Banyak

Mari berlatih memakai method dengan mengimplementasikan method kedua pada struct Rectangle. Kali ini kita ingin sebuah instance Rectangle menerima instance Rectangle lain dan mengembalikan true kalau Rectangle kedua itu bisa muat sepenuhnya di dalam self (Rectangle pertama); selain itu, ia harus mengembalikan false. Artinya, begitu kita sudah mendefinisikan method can_hold, kita ingin bisa menulis program berikut:

Nama berkas: src/main.rs

fn main() {
    let rect1 = Rectangle {
        width: 30,
        height: 50,
    };
    let rect2 = Rectangle {
        width: 10,
        height: 40,
    };
    let rect3 = Rectangle {
        width: 60,
        height: 45,
    };

    println!("Can rect1 hold rect2? {}", rect1.can_hold(&rect2));
    println!("Can rect1 hold rect3? {}", rect1.can_hold(&rect3));
}

Output yang diharapkan akan terlihat seperti berikut, karena kedua dimensi rect2 lebih kecil dari dimensi rect1, tapi rect3 lebih lebar dari rect1: 

Can rect1 hold rect2? true
Can rect1 hold rect3? false

Kita tahu kita ingin mendefinisikan sebuah method, jadi ia akan ada di dalam blok impl Rectangle. Nama method-nya akan jadi can_hold, dan ia akan menerima immutable borrow dari Rectangle lain sebagai parameter. Kita bisa tahu tipe parameternya dengan melihat kode yang memanggil method itu: rect1.can_hold(&rect2) mengoper &rect2, yaitu immutable borrow ke rect2, sebuah instance Rectangle. Ini masuk akal karena kita cuma perlu membaca rect2 (bukan menulis, yang berarti kita akan butuh mutable borrow), dan kita ingin main tetap memegang ownership rect2 supaya kita bisa memakainya lagi setelah memanggil method can_hold. Nilai kembalian can_hold akan berupa Boolean, dan implementasinya akan memeriksa apakah lebar dan tinggi self lebih besar dari lebar dan tinggi Rectangle lainnya. Mari tambahkan method baru can_hold ke blok impl sebelumnya:

Nama berkas: src/main.rs

impl Rectangle {
    fn area(&self) -> u32 {
        self.width * self.height
    }

    fn can_hold(&self, other: &Rectangle) -> bool {
        self.width > other.width && self.height > other.height
    }
}

Ketika kita jalankan kode ini dengan fungsi main sebelumnya, kita akan dapat output yang kita inginkan. Method bisa menerima banyak parameter yang kita tambahkan ke signature-nya setelah parameter self, dan parameter-parameter itu bekerja persis seperti parameter di fungsi biasa.

Associated Function

Semua fungsi yang didefinisikan di dalam blok impl disebut associated function karena mereka diasosiasikan dengan tipe yang disebut setelah impl. Kita bisa mendefinisikan associated function yang tidak punya self sebagai parameter pertamanya (dan karena itu bukan method) karena mereka tidak butuh instance dari tipe itu untuk bekerja. Kita sudah memakai satu fungsi seperti ini: fungsi String::from yang didefinisikan pada tipe String.

Associated function yang bukan method sering dipakai untuk constructor yang mengembalikan instance baru dari struct-nya. Fungsi ini sering dinamai new, tapi new bukan nama khusus dan tidak dibangun ke dalam bahasanya. Misalnya, kita bisa memilih menyediakan associated function bernama square yang menerima satu parameter dimensi dan memakainya baik sebagai lebar maupun tinggi, sehingga lebih mudah membuat Rectangle berbentuk persegi tanpa harus menentukan nilai yang sama dua kali:

Nama berkas: src/main.rs

impl Rectangle {
    fn square(size: u32) -> Self {
        Self {
            width: size,
            height: size,
        }
    }
}

Keyword Self di tipe kembalian dan di badan fungsinya adalah alias untuk tipe yang muncul setelah keyword impl, yang dalam kasus ini adalah Rectangle.

Untuk memanggil associated function ini, kita pakai sintaks :: dengan nama struct-nya; contohnya let sq = Rectangle::square(3);. Fungsi ini di-namespace oleh struct-nya: sintaks :: dipakai baik untuk associated function maupun namespace yang dibuat oleh module. Kita akan bahas module di Bab 7.

Banyak Blok impl

Setiap struct diizinkan punya banyak blok impl. Misalnya, kode can_hold sebelumnya setara dengan kode berikut, yang menaruh setiap method di blok impl-nya masing-masing: 

impl Rectangle {
    fn area(&self) -> u32 {
        self.width * self.height
    }
}

impl Rectangle {
    fn can_hold(&self, other: &Rectangle) -> bool {
        self.width > other.width && self.height > other.height
    }
}

Tidak ada alasan khusus untuk memisahkan method-method ini menjadi beberapa blok impl di sini, tapi ini sintaks yang valid. Kita akan lihat kasus di mana banyak blok impl berguna di Bab 10, saat kita membahas tipe generik dan trait.

Ringkasan Bab 5

  • Struct membiarkanmu membuat tipe custom yang bermakna untuk domainmu, dengan mengelompokkan data terkait dan memberi nama pada setiap bagiannya.
  • Di blok impl, kamu mendefinisikan associated function — method (parameter pertama self/&self/&mut self) dan constructor tanpa self (dipanggil lewat Tipe::nama_fungsi(...)).
  • &self untuk membaca, &mut self untuk mengubah, dan self (tanpa &) untuk mengambil ownership instance-nya — pilih sesuai kebutuhan method-nya.

Tapi struct bukan satu-satunya cara kamu bisa membuat tipe custom: mari kita beralih ke fitur enum Rust untuk menambah alat lain ke toolbox-mu.
